# LoopX — Feature Dossier
Registry: #138 | Category: 06 | Verified: 5,132★, Apache-2.0 (since v0.4.8; MIT before), pushed 2026-08-25

Adopt-tier dossier — the ledger's strongest R11 prior art ("durable goals + governed handoffs + evidence logs as first-class artifacts", 09-feature-extraction:256). Ticket directive: DETAIL the handoff/governance mechanics thoroughly. This is a Python 3.11+ stdlib-only state kernel that runs *on top of* Codex/Claude Code/Cursor/dsh rather than replacing them — architecturally the closest public artifact to LastHarness's kernel/worker split found to date.

## Feature inventory
- **Durable control-plane state in one compact layer**: `objective + gates + todos + scope + evidence + quota` persists under `.loopx/` (+ `.codex/goals/`, `.local/`, gitignored) so "work that began last week resumes exactly where the last bounded turn stopped instead of living in chat memory" [VERIFIED-fetched:https://raw.githubusercontent.com/huangruiteng/loopx/main/README.md]
- **The core tick — quota-gated continuation, five commands**: `loopx quota should-run` (should this registered agent act now?) → `todo claim` (who owns this slice?) → `todo update` (what changed?) → `refresh-state` (what should the next turn see?) → `quota spend-slot` (account for a completed, validated slice). "Automatic turns must check quota first and append spend only after validated writeback. Quiet skips, preflight failures, and dry-run previews do not spend" [VERIFIED-fetched:https://raw.githubusercontent.com/huangruiteng/loopx/main/README.md]
- **Peer-agent handoff without a leader**: "Registered agents are peers. Claims, leases, task boundaries, capabilities, and typed continuation decide who acts next; no durable leader identity is required." Peer agents use `todo claim` before delivery and `todo update` after validation "so ownership and evidence remain visible" [VERIFIED-fetched:https://raw.githubusercontent.com/huangruiteng/loopx/main/README.md]
- **Kernel/capability/provider boundary model**: Kernel owns durable goal/todo/gate/evidence/quota/recovery/scheduling truth; Capability defines "a stable, provider-neutral contract for producing one bounded, verifiable caller outcome"; Provider returns "bounded observations, effect results, and readback". Execution path `Agent → Capability → Provider`; control path returns `Provider readback → Capability transition → Kernel`. Host declarations like `--available-capability shell` are "runtime capacities … not permission grants. The effective capability still applies its own policy and authority checks before proposing a transition" [VERIFIED-fetched:https://raw.githubusercontent.com/huangruiteng/loopx/main/README.md]
- **Concrete user gates + audited safe fallback**: "human judgment needed? → ask a concrete question and wait"; "When a user gate blocks one lane, a separately audited safe fallback may continue, but it must not bypass the gate" [VERIFIED-fetched:https://raw.githubusercontent.com/huangruiteng/loopx/main/README.md]
- **Scheduler hint + acknowledgment protocol**: cadence follows `quota should-run.scheduler_hint`; Codex App automations acknowledge via returned `ack_hint.cli_args` — advisory pacing, explicitly "not a host-enforced gate" on some facades [VERIFIED-fetched:https://raw.githubusercontent.com/huangruiteng/loopx/main/README.md]
- **Cross-runtime facades all re-enter one gate**: adapters for Codex App/CLI, Claude Code (`claude_goal_mode`), KunlunCode native Goal adapter ("LoopX writes completion and quota only after strict verification"), OpenCode command facade, Pi goal extension gated by quota (`loopx_goal_activate` + `agent_settled`), ZCode/Antigravity skill facades, DeepSeek Harness turn adapter — every continuation enters through `quota should-run` [VERIFIED-fetched:https://raw.githubusercontent.com/huangruiteng/loopx/main/README.md]
- **Capability catalog as outcome-owned work lanes**: issue-fix (rolling repo context + revision-stamped fix knowledge), change-quality ("qualify the exact final diff before delivery"), integration-branch reconcile, explore (hypothesis-preserving research w/ measurable offline evaluation), decision-context ("rebase decisions on current evidence and verified outcomes"), periodic-report ("scheduled or progress-triggered reports with receipts"); each detail page reports "user value, maturity, provider readiness, entry commands, write boundaries, protocols, and durable validation" [VERIFIED-fetched:https://raw.githubusercontent.com/huangruiteng/loopx/main/README.md]
- **review-packet operator surface**: "compact owner-facing view of decisions, evidence, validation, and unresolved gates"; dashboard is read-first — "the browser is a projection; LoopX state remains the source of truth"; session-dash fleet panel auto-refreshes; Lark Kanban external projection where "LoopX remains authoritative" [VERIFIED-fetched:https://raw.githubusercontent.com/huangruiteng/loopx/main/README.md]
- **Auto-research multi-role demo**: proposer, executor, evaluator/promoter iterate in parallel while todo/quota/evidence/targeted-wake stay visible; deterministic CPU evaluator; dev/held-out commands in-repo [VERIFIED-fetched:https://raw.githubusercontent.com/huangruiteng/loopx/main/README.md]
- **Reward Memory experiment**: provider-neutral reward memory for named registered agents, "ignored, default-off project configuration", OpenViking one provider option [VERIFIED-fetched:https://raw.githubusercontent.com/huangruiteng/loopx/main/README.md]
- **Evidence-strength labeling culture**: showcases carry explicit labels (owner-run redacted vs reproducible demo vs user report); "not a claim of continuous compute"; elapsed-lifetime ≠ execution-hours distinction stated twice; star-history graph generated every 6h from stargazer timestamps published only when rows match GitHub's count [VERIFIED-fetched:https://raw.githubusercontent.com/huangruiteng/loopx/main/README.md]
- **Boundary checks before publication**: `loopx check --scan-path README.md --scan-path docs/` for private-data leakage pre-release; public/private boundary doc maintained [VERIFIED-fetched:https://raw.githubusercontent.com/huangruiteng/loopx/main/README.md]

| Quota-gated tick: should-run → claim → update → refresh-state → spend-after-validated-writeback | ⚙ Feature adoption | §16.5 ephemeral dispatch gating + §16.6 completion admission | The cleanest published formulation of "no continuation without validated outcome": spend is appended only post-validation; skips/failures cost nothing. This is the accounting discipline the decision log needs for budget enforcement. |
| Typed handoff artifacts (claims, leases, task boundaries, typed continuation) | ⚙ Feature adoption | R11 kernel-composed handoff packet (11-department-blueprints:128) | Directly answers R11's open question — what goes IN a handoff packet: ownership claim, lease expiry, scope boundary, capability set, typed continuation token, evidence pointer. Compose this into the kernel's named artifact. |
| Concrete user gates; audited safe fallback that cannot bypass the gate | ⚙ Feature adoption | §16.10 approval-gate semantics | Two rules worth copying verbatim: gates ask *concrete questions*, never vague "waiting for owner"; fallback lanes run concurrently but are separately audited and structurally unable to bypass the blocked gate. |
| Kernel/capability/provider split with readback-driven transitions | 🧩 Mechanism only (confirmation) | §4.4 kernel mediation; verifier dept | Same shape as LastHarness's worker→kernel result admission. | scheduler_hint + ack_hint acknowledgment loop | 🧩 Mechanism only | §14.6 scheduled re-checks | Advisory pacing with explicit acknowledgment beats fire-and-forget cron; adopt hint+ack as the notification-queue re-check protocol. Honest about which hosts can't enforce it. |

| Auto-research proposer/executor/evaluator-promoter roles | 🧩 Mechanism only | Multi-worker dispatch pattern within ONE env | Roles coordinate through kernel state, not peer channels — compatible shape if all three are ephemeral workers over local data with a deterministic evaluator. |

## Notable absences
No crypto/tamper-evidence on the evidence log — writeback validation is policy-level (strict verification in adapters), not integrity-level; LastHarness's immutable SQLite decision log is stronger. Quota is token/budget-shaped but no per-tool deny-lists at README depth — authorization rides capability contracts rather than enumerated allow-lists. No egress gateway concept at all (providers are BYO). Windows support is PowerShell-7-native but second-class (POSIX first). Evidence-strength labels exist for showcases but not for machine-consumed evidence records themselves.
