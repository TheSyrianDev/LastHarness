# AgentMemory — Feature Dossier
Registry: #140 | Category: 02 | Verified: 27,408★, Apache-2.0, pushed 2026-08-24

Note-tier dossier (ledger: "Benchmark-topped persistent memory — compare against adopted staleness-anchor design (#5) before any swap", 09-feature-extraction:258). Ticket questions this dossier answers: what is the architecture, and **what do its benchmarks actually measure?** Verdict up front: they measure *retrieval recall on QA over stored sessions* — a read-side metric. They do not measure fact staleness, write-side governance, or correctness-over-time, which is exactly what LastHarness's adopted staleness-anchor design (#5 TokenGoat Mem: facts anchored to file/git revisions, recall re-validates anchors, filters stale) is for. The two designs are complementary axes, not substitutes.

## Feature inventory
- **Architecture**: Node server on the pinned iii-engine (v0.11.2) exposing REST/MCP HTTP :3111, iii streams :3112, real-time viewer :3113, iii worker WS :49134; storage "None (SQLite + iii-engine)" — zero external DBs; state lives outside the repo by default (`~/.local/share/agentmemory` etc., `--data-dir`/`AGENTMEMORY_DATA_DIR` override) [VERIFIED-fetched:https://raw.githubusercontent.com/rohitg00/agentmemory/main/README.md]
- **Auto-capture via lifecycle hooks**: 12 hooks in the Claude Code plugin (SessionStart/UserPromptSubmit/PreToolUse/PostToolUse/…), 22 for OpenCode, 6 for Codex/Devin/Hermes — capture happens as sessions run, "silently captures what your agent does, compresses it into searchable memory, and injects the right context when the next session starts"; LLM-written observation compression only when `AGENTMEMORY_AUTO_COMPRESS=true` [VERIFIED-fetched:https://raw.githubusercontent.com/rohitg00/agentmemory/main/README.md]
- **Hybrid retrieval**: BM25 + vector + structural graph matches fused via RRF; keyless mode disables vectors (BM25-only); optional local embeddings (`EMBEDDING_PROVIDER=local`, Xenova/all-MiniLM-L6-v2, one-time download then on-device inference); 54 MCP tools incl. `memory_smart_search`, `memory_recall`, `memory_governance_delete` [VERIFIED-fetched:https://raw.githubusercontent.com/rohitg00/agentmemory/main/README.md]
- **Benchmark #1 — LongMemEval-S (ICLR 2025, public 500-Q)**: agentmemory R@5 95.2%, R@10 98.6%, MRR 88.2% vs BM25-only fallback 86.2%/94.6%/71.5%; reproducible via an adapter-pluggable harness (`eval/README.md`) with published scorecards [VERIFIED-fetched:https://raw.githubusercontent.com/rohitg00/agentmemory/main/README.md]
- **Benchmark #2 — in-house coding-agent-life-v1**: 15-session corpus; hybrid P@5 0.240 / R@1.000 / 15-of-15 top-5 hits at "the P@5 math ceiling for this corpus" vs grep baseline 0.227/0.967; README itself concedes "This benchmark is small and gold-sparse; the larger LongMemEval-S below differentiates better" and that the lift is "recall + temporal, not aggregate precision" [VERIFIED-fetched:https://raw.githubusercontent.com/rohitg00/agentmemory/main/README.md]
- **What the competitor table measures — and admits**: comparison table mixes agentmemory's own measured R@5 with competitors' published LoCoMo numbers and vendor self-reported figures (MemPalace ~96.6%, TencentDB PersonaMem 76% flagged "self-reported … not independently reproduced"); footnote states "ballpark only, not a head-to-head on identical data" [VERIFIED-fetched:https://raw.githubusercontent.com/rohitg00/agentmemory/main/README.md]
- **Token-savings claim**: ~170K tokens/yr (~$10) vs ~650K LLM-summarized (~$500) vs 19.5M full-context-paste; ~1,900 tokens/session injection budget [VERIFIED-fetched:https://raw.githubusercontent.com/rohitg00/agentmemory/main/README.md]
- **Memory lifecycle**: "4-tier consolidation + decay + auto-forget" — the decay/auto-forget tier is the closest architectural contact with staleness handling, but it is time/usage-decay, not revision-anchored validation [VERIFIED-fetched:https://raw.githubusercontent.com/rohitg00/agentmemory/main/README.md]
- **Multi-agent coordination surface**: "MCP + REST + leases + signals" across all wired agents sharing one server [VERIFIED-fetched:https://raw.githubusercontent.com/rohitg00/agentmemory/main/README.md]
- **Session Replay viewer**: timeline scrubbing of prompts/tool calls/results/responses with play/pause/speed; `import-jsonl` backfills Claude Code transcripts — with the documented trap that Claude Code's `cleanupPeriodDays` (default 30) auto-deletes older JSONL before import can reach it [VERIFIED-fetched:https://raw.githubusercontent.com/rohitg00/agentmemory/main/README.md]
- **17 skills** (9 invocable: remember/recall/recap/handoff/forget/lesson/commit-context/commit-history/session-history; 8 reference) installable into 50+ agents via skills CLI; per-agent adapters for 20+ hosts [VERIFIED-fetched:https://raw.githubusercontent.com/rohitg00/agentmemory/main/README.md]

## Per-feature verdict
| Feature | Type | LastHarness landing | Rationale |
|---|---|---|---|
| Staleness handling (4-tier consolidation + time decay + auto-forget) | 🧩 Mechanism only — compare, don't swap | §6.3 department-scoped gated memory w/ adopted #5 staleness anchors | The ledger's comparison mandate, resolved: agentmemory decays facts by TIME and usage; #5 anchors facts to file/git REVISIONS and re-validates on recall. For code facts, revision anchoring is strictly stronger — code truth changes by commit, not by clock. Adopt nothing here; record decay-tiers as a supplementary ranking signal for non-code facts (preferences, decisions) where no anchor exists. |
| Benchmarks (LongMemEval-S 95.2% R@5; in-house corpus) | 🧩 Evidence note | Evaluation harness design for any LastHarness memory layer | What they measure: retrieval hit-rate on QA over stored sessions. What they don't measure: whether recalled facts are still TRUE (staleness), who may read them (department ACLs), or write governance. Useful as the read-side eval template if LastHarness ever builds a session-recall surface — run the same adapter-pluggable harness shape. |
| Hook-based silent auto-capture of everything | ❌ Conflict-skip | §6.3 gated writes; deny-by-default posture | Capture-everything-by-default inverts LastHarness's doctrine: memory enters departments through typed, allow-listed writes with provenance, not ambient hook sweeps. The 12-hook plumbing is the mechanism to NOT copy even though the ergonomics are real. |
| Resident four-port memory server shared by all agents | ❌ Conflict-skip | §16.5 ephemeral workers; §4.4 kernel mediation | A standing always-on server with its own worker protocol is exactly the standing-process pattern excluded. If session recall ever lands, it lives kernel-side as a library over the decision log, not as a sibling daemon every CLI attaches to. |
| Keyless BM25-first degradation path (+local embeddings option) | 🧩 Mechanism only | Local-first inference; hardware-tiered model packs | Correct ordering: lexical search works with zero model deps; embeddings are an upgrade that downloads once then runs on-device. Same graceful ladder LastHarness's model packs assume. |
| Leases + signals for multi-agent memory access | 🧩 Mechanism only | Kernel-mediated access vocabulary | Independent use of leases/signals vocabulary for shared-store access — consistent with kernel-mediated routing; nothing beyond terminology to take. |
| Session replay + import-jsonl w/ cleanupPeriodDays warning | 🧩 Design note | Decision-log render (R7); data-retention policy input | Two lessons: replay-from-events is the right owner-console primitive (LastHarness already keeps better events), and upstream tools silently destroying history (30-day JSONL cleanup) is a retention-policy hazard worth a line in ops docs. |
| `memory_governance_delete` tool | 🧩 Design note | Right-to-erasure hook on gated stores | A first-class delete verb in the tool surface is good governance hygiene; LastHarness's immutable decision log stays append-only, but departmental *working* stores need exactly this named operation. |

## Notable absences
No revision/git anchoring anywhere in the primary source — the decisive gap vs adopted design #5. No ACLs, scoping, or multi-user story: one server, all agents, all memories ("One server, memories shared across all of them" is the pitch, not a bug). No provenance metadata on stored observations beyond origin channel on imports. No encryption-at-rest discussion. Benchmarks never evaluate precision under adversarial/stale corpora — recall-heavy scoring flatters append-mostly stores. Honest about most of this in footnotes, which is why it lands as a respected note-tier entry rather than adoption.
