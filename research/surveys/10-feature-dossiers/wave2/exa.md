# Exa MCP Server — Feature Dossier
Registry: #94 | Category: 03 | Verified: 4,919 stars, MIT, last push 2026-08-21

## Feature inventory
- Hosted MCP endpoint `https://mcp.exa.ai/mcp` (streamable-http) installable into most clients; also packaged as Agent Plugin / Claude plugin / Codex plugin, plus a local npm server variant [VERIFIED-fetched:https://raw.githubusercontent.com/exa-labs/exa-mcp-server/main/README.md]
- Tool partitioning with minimal defaults: only `web_search_exa` ("search the web… clean, ready-to-use content") and `web_fetch_exa` ("full content as clean markdown from one or more URLs") are on by default [VERIFIED-fetched:https://raw.githubusercontent.com/exa-labs/exa-mcp-server/main/README.md]
- Opt-in tools appended via the URL `?tools=` parameter **replacing** defaults (`?tools=web_search_exa,web_fetch_exa,agent_run`): `web_search_advanced_exa` adds filters/domains/dates/highlights/summaries/subpage crawling; `agent_run` runs Exa Agent for multi-step research/list-building/enrichment/structured output and requires auth [VERIFIED-fetched:https://raw.githubusercontent.com/exa-labs/exa-mcp-server/main/README.md]
- Contents modes as exposed in-repo: default clean-markdown normalization for fetch/search output; highlights, summaries, and subpage crawling gated behind the advanced tool [VERIFIED-fetched:https://raw.githubusercontent.com/exa-labs/exa-mcp-server/main/README.md]
- Auth ladder: anonymous rate-limited access → OAuth preferred (JWT attached automatically) → API key via `Authorization: Bearer`, `x-api-key`, or `?exaApiKey=` [VERIFIED-fetched:https://raw.githubusercontent.com/exa-labs/exa-mcp-server/main/README.md]
- Agent Skills shipped alongside tools: `search` (deep-research orchestrator) and `exa-agent`; skills "add orchestration on top" of MCP-only setups [VERIFIED-fetched:https://raw.githubusercontent.com/exa-labs/exa-mcp-server/main/README.md]
- Orchestrator skill mechanics: complexity triage (Extremely Simple → Complex) deciding zero-vs-subagent dispatch, mandatory user confirmation on ambiguous depth, parallel subagents with token isolation ("keep raw search output out of your context window"), 3–5 searches per subagent sizing [VERIFIED-fetched:https://raw.githubusercontent.com/exa-labs/exa-mcp-server/main/skills/search/SKILL.md]
- `sources_reviewed` accounting line passed verbatim to every subagent and summed at compile time (e.g. calls with numResults 10+10+5 → `sources_reviewed: 25`) [VERIFIED-fetched:https://raw.githubusercontent.com/exa-labs/exa-mcp-server/main/skills/search/SKILL.md]
- Search mechanics reference: vector-embedding semantic similarity (no boolean operators, no exact-phrase forcing), `numResults` sizing table (5 named-entity / 10 filtered / 15 broad discovery, never >25), inline `category:` filters (company/publication/news/personal site/people), query-diversity-by-angle doctrine, explicit date calculation before querying [VERIFIED-fetched:https://raw.githubusercontent.com/exa-labs/exa-mcp-server/main/skills/search/references/searching.md]
- Compile-stage discipline: dedupe by URL then merge same-entity fields keeping best data, coverage-gap follow-up searches, source-quality weighting (practitioners over commentators), red-team pass before synthesis [VERIFIED-fetched:https://raw.githubusercontent.com/exa-labs/exa-mcp-server/main/skills/search/SKILL.md]

## Notable absences
The repo documents no self-hosted or local-inference path for the neural index itself — similarity search is irreducibly Exa-cloud, so nothing here can run fully in-boundary (unlike SearXNG). Fine-grained API contents modes (raw text vs highlights vs summary payloads, live-crawl behavior) are not documented in this repo's README/skill files beyond the advanced-tool summary — deeper semantics live in docs.exa.ai and were not fetched. No result caching/replay, no per-query audit export beyond the orchestrator's own accounting convention, no rate-limit response schema comparable to Tavily's structured limit exception.
