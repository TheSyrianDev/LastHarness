# Catalyst — Feature Dossier
Registry: #58 | Category: 06 | Verified: 32★, AGPL-3.0, last push 2026-08-15 (repo-verify.txt 2026-08-24)

Imbue's semi-autonomous AI scientist: evolution-based theory discovery and verifiable-goal optimization built ON TOP of installed coding-agent harnesses. The verification/fitness machinery is the valuable part; the execution model — >100 frontier-API subagents per workflow, ~$1,000/workflow on Opus API billing — is the warning.

## Feature inventory
- Two research modalities: Explaining Phenomena (autonomously develops a theory with testable predictions for an observed phenomenon; can also fill gaps in and auto-correct a user-provided draft) and Verifiable Goal Solving/Optimization (solves goals verifiable through code or optimizes a measurable metric) [VERIFIED-fetched:https://raw.githubusercontent.com/imbue-ai/catalyst/master/README.md]
- Fitness verification mechanics: candidates are "checked against empirical data/verification scripts"; verifiable goals require a user-specified verification script Y or measurement method Y upfront; phenomena must be reproducible/probeable via programmatic Python experiments run on your own computer; problems lacking clear programmatic verification criteria are declared out of scope [VERIFIED-fetched:https://raw.githubusercontent.com/imbue-ai/catalyst/master/README.md]
- Experiment runtime clamp: any single experiment limited to 30 minutes by default, adjustable only via `CATALYST_EXPERIMENT_TIMEOUT_SECS`; only verifiable-goal workflows optimize experiment efficiency [VERIFIED-fetched:https://raw.githubusercontent.com/imbue-ai/catalyst/master/README.md]
- Adversarial review-refinement loops: one set of agents continuously improves the theory/solution candidate while separate INDEPENDENT agents falsify its statements, identify edge cases, and highlight limits [VERIFIED-fetched:https://raw.githubusercontent.com/imbue-ai/catalyst/master/README.md]
- Evolution-inspired search: maintains a population of competing candidates that are repeatedly ranked against each other and against empirical data/verification scripts; most promising selected for further refinement and branching [VERIFIED-fetched:https://raw.githubusercontent.com/imbue-ai/catalyst/master/README.md]
- Harness substrate: drives EXISTING installed agent CLIs — Claude Code (`claude -p` or mngr), Gemini CLI (`gemini -p`), Antigravity CLI (`agy -p`), Codex CLI (`codex exec`) — billed directly by the provider off each harness's existing authentication [VERIFIED-fetched:https://raw.githubusercontent.com/imbue-ai/catalyst/master/README.md]
- Cost disclosure table: evolution workflows frequently compose >100 subagents; Develop Theory (Evolution) ≈ $1,000 API-billed on Opus 4.8 (~$150–500 on cheaper Claude models), Solve Verifiable Goal (Evolution) ≈ $75–500, linear variants cheaper; explicit warning to monitor provider spend dashboards [VERIFIED-fetched:https://raw.githubusercontent.com/imbue-ai/catalyst/master/README.md]
- Step-type model overrides as cost control: ~65% of tokens go to review/scoring steps which tolerate weaker models — configure strongest model ONLY for development steps [VERIFIED-fetched:https://raw.githubusercontent.com/imbue-ai/catalyst/master/README.md]
- Manual add-on steps menu (review theory correctness, propose refinements, evaluate candidates) plus mid-research steering docs for redirecting ongoing runs [VERIFIED-fetched:https://raw.githubusercontent.com/imbue-ai/catalyst/master/README.md]
- Sandbox posture: Claude Code, Gemini CLI, and Codex CLI harnesses run in sandbox; Antigravity does not (linked upstream issue) [VERIFIED-fetched:https://raw.githubusercontent.com/imbue-ai/catalyst/master/README.md]
- Stable-branch discipline: install instructions pin `git checkout stable` for users vs main [VERIFIED-fetched:https://raw.githubusercontent.com/imbue-ai/catalyst/master/README.md]

## Notable absences
No local-model mode whatsoever — every supported harness is a frontier-API subscription product, so nothing here can execute within a no-egress boundary as-is. No budget ceiling enforcement: costs are disclosed and monitored manually. No durable knowledge capture: discovered theories/solutions land as run artifacts, not a queryable evidence base with provenance back to which verification script passed. Verification is single-shot per candidate (pass/fail against the script) with no regression re-verification documented when candidates mutate. Domain ceiling is self-declared (ML/deep-learning-theory phenomena, computationally probeable only). Community mass is tiny (32★) — bus-factor risk for pattern reuse.
