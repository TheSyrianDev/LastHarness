# Oh My Hermes — Feature Dossier
Registry: #68 | Category: 05 | Verified: 854 stars, license none per repo-verify (README badge claims MIT — unresolved mismatch), last push 2026-07-28

SCOPE: opinionated skill/workflow layer (36 skills, 7 agents, 6 workflows) installed into the Hermes Agent runtime. The layer itself is config/scripts, not a service; verdicts separate the excluded harness/residency model from extractable workflow-governance patterns.

## Feature inventory
- Installer drops 36 skills, 7 agent role definitions, and 6 workflows into an existing Hermes install (`~/.hermes/skills|agents|workflows`); OMH itself "is not deployed as an app" [VERIFIED-fetched:https://raw.githubusercontent.com/Salomondiei08/oh-my-hermes/main/README.md]
- Seven-role lifecycle org: CTO (roadmap/delegation/escalation) over Product, Designer, Builder, Reviewer, Security, Ops — coordinated through Hermes Kanban (`hermes kanban watch`) with memory + cron + completion evidence [VERIFIED-fetched:https://raw.githubusercontent.com/Salomondiei08/oh-my-hermes/main/README.md]
- Understand → Design → Build → Check → Ship → Learn pipeline; work can start from idea, customer feedback, production logs, analytics, or an issue; issues/PRs are "delivery evidence, not the roadmap" [VERIFIED-fetched:https://raw.githubusercontent.com/Salomondiei08/oh-my-hermes/main/README.md]
- Onboarding discipline: reads the project before asking, at most three optional questions, recommended defaults proceed when skipped, avoids duplicate crons [VERIFIED-fetched:https://raw.githubusercontent.com/Salomondiei08/oh-my-hermes/main/README.md]
- Approval perimeter: only irreversible actions require founder approval (production release, rollback, public posting, licensed media, payment, destructive account changes); `await-merge-approval` implements a YES / NO / CLOSE / LATER response vocabulary [VERIFIED-fetched:https://raw.githubusercontent.com/Salomondiei08/oh-my-hermes/main/README.md]
- Cron-driven autonomy on a $5/mo VPS where "Hermes runs 24/7": hourly CTO loop, 15-minute Ops health checks, daily security assessment + morning report [VERIFIED-fetched:https://raw.githubusercontent.com/Salomondiei08/oh-my-hermes/main/README.md]
- Dead-letter failure recovery: `run-cron-safe.sh` wraps cron jobs writing failed context to dead-letter logs; `failure-recovery` alerts the founder; `reset-runtime` backs up then clears stale state without deleting credentials [VERIFIED-fetched:https://raw.githubusercontent.com/Salomondiei08/oh-my-hermes/main/README.md]
- Builder hygiene: claims highest-priority ready ticket, commits after each logical unit, scans `git diff --staged` before every commit and never commits `.env`/secrets, hands PR summary to Security/QA; cannot merge or deploy [VERIFIED-fetched:https://raw.githubusercontent.com/Salomondiei08/oh-my-hermes/main/README.md]
- Security severity table with mandatory actions: Critical = block merge + immediate Telegram alert; High = block merge + fix instructions on PR; Medium = comment, fix next sprint; Low = log to memory + weekly report; tool-backed gates (Gitleaks, Semgrep, OSV-Scanner) and "never claim an unavailable scanner passed" [VERIFIED-fetched:https://raw.githubusercontent.com/Salomondiei08/oh-my-hermes/main/README.md]
- Reviewer gate: `gh pr checks` build verification plus preview health check (HTTP 200, `status: ok`, <3000 ms) before APPROVE; founder summary in plain English (user-visible change, functions changed, response time) [VERIFIED-fetched:https://raw.githubusercontent.com/Salomondiei08/oh-my-hermes/main/README.md]
- Ops three-layer health check (app `/api/health`, Supabase connection, Vercel logs), hourly log dedup escalating only actionable changes, incident retry once after 60 s, rollback offer window (<2 h since deploy) requiring explicit YES [VERIFIED-fetched:https://raw.githubusercontent.com/Salomondiei08/oh-my-hermes/main/README.md]
- Engine routing: `choose-engine` sends ops/config to Hermes terminal, single-file fixes to Codex, multi-file features to Claude Code [VERIFIED-fetched:https://raw.githubusercontent.com/Salomondiei08/oh-my-hermes/main/README.md]
- Staged credential-on-first-use: creds requested only at first action needing them, stored `~/.hermes/.env` user-only permissions; Buffer posts dry-run first; Seedance shows payload + estimated cost before approval; never paste credentials into chat [VERIFIED-fetched:https://raw.githubusercontent.com/Salomondiei08/oh-my-hermes/main/README.md]
- Project-switch isolation: switching product context without mixing repo, URL, logs, or approvals across projects [VERIFIED-fetched:https://raw.githubusercontent.com/Salomondiei08/oh-my-hermes/main/README.md]
- Optional GBrain memory backbone (self-updating knowledge graph of people/companies/decisions/deployments); npm-squatter warning for gbrain [REPORTED-unverified — external repo linked from README, not fetched]

## Notable absences
No kernel/policy layer: role separation is convention enforced by prompts and scripts, with no technical boundary preventing the CTO session from doing specialist work or agents contacting each other outside kanban. No audit trail beyond Hermes memory and git history; approval records aren't tamper-evident. Security scanning depends on whatever tools exist in the Hermes environment. License metadata conflicts (GitHub API: none; README badge: MIT) — provenance must be resolved before any code reuse. Deep docs live in-repo under docs/ and were README-level verified only.
