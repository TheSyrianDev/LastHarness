# OpenViking — Feature Dossier
Registry: #20 | Category: 02 | Verified: 32,760★, AGPL-3.0, last push 2026-08-24 (repo-verify.txt 2026-08-24)

ByteDance/volcengine context database unifying agent memory, knowledge RAG, and skills as one `viking://` virtual filesystem. Execution is a self-hosted Python HTTP service (`openviking-server`) with a thin `ov` CLI — infra shape, not an agent — but its agent-integration model injects recall directly into vendor clients, bypassing any kernel.

## Feature inventory
- Unified context filesystem under `viking://`: memories, resources, and skills each get a URI; agents browse their own context deterministically with `ls`, `tree`, `find`, `grep` instead of querying a black-box vector store [VERIFIED-fetched:https://raw.githubusercontent.com/volcengine/OpenViking/main/README.md]
- Three-tier context processing on write: every entry compiled to L0 abstract (~100 tokens), L1 overview (~2k tokens), L2 full details loaded on demand; directories carry their own `.abstract`/`.overview` so relevance is judged before any file is read [VERIFIED-fetched:https://raw.githubusercontent.com/volcengine/OpenViking/main/README.md]
- Directory recursive retrieval: vector search first locates the highest-scoring directory, then drills down layer by layer so results arrive with surrounding context intact [VERIFIED-fetched:https://raw.githubusercontent.com/volcengine/OpenViking/main/README.md]
- Observable retrieval trajectories: each query preserves its directory-browsing path so a wrong result can be traced to the exact route that produced it [VERIFIED-fetched:https://raw.githubusercontent.com/volcengine/OpenViking/main/README.md]
- Sessions become memory: after a session commits, asynchronous extraction writes user preferences and agent experience into long-term memory [VERIFIED-fetched:https://raw.githubusercontent.com/volcengine/OpenViking/main/README.md]
- Standalone HTTP service deployment (`openviking-server`, background/nohup or Docker production guide) with interactive `init` wizard, `doctor` config validation, and thin `ov` client CLI (also npm/cargo installs) [VERIFIED-fetched:https://raw.githubusercontent.com/volcengine/OpenViking/main/README.md]
- Provider setup includes local Ollama: the wizard detects and can install the Ollama runtime and pull models suited to your hardware; Volcengine/OpenAI/Kimi/GLM also supported [VERIFIED-fetched:https://raw.githubusercontent.com/volcengine/OpenViking/main/README.md]
- Agent integrations injecting recall + auto-committing session memory directly into Claude Code, Codex, OpenClaw, Hermes, Cursor, TRAE, OpenCode, pi, MCP clients, and LangChain/LangGraph [VERIFIED-fetched:https://raw.githubusercontent.com/volcengine/OpenViking/main/README.md]
- OpenViking Helper desktop console (beta, macOS/Windows): detects local agents and configures plugin/MCP/Hook integrations; parses Claude Code/Codex/Trae session traces to show recall, prompt-injection, MCP, capture, and commit events; browses local memory/rules/`SKILL.md` and syncs them into OpenViking [VERIFIED-fetched:https://raw.githubusercontent.com/volcengine/OpenViking/main/README.md]
- VikingBot: an AI agent framework built on top of OpenViking, bundled in and started by default alongside the server in the official Docker image [VERIFIED-fetched:https://raw.githubusercontent.com/volcengine/OpenViking/main/README.md]
- Self-published benchmarks: LoCoMo long-conversation memory accuracy 80–83% (vs 24–57% native) across three agent integrations with 34–91% token-input reduction; tau2-bench success +6.87/+11.87pp — evaluated by the project itself, reproduction scripts in `./benchmark` [VERIFIED-fetched:https://raw.githubusercontent.com/volcengine/OpenViking/main/README.md]
- Per-user context tree `user/{user_id}/` with `memories/`, `resources/`, `skills/`, and `peers/` namespaces [VERIFIED-fetched:https://raw.githubusercontent.com/volcengine/OpenViking/main/README.md]
- Commercial editions answer "who operates it": managed SaaS on Volcano Engine, or self-managed BYOC/air-gapped offline deployments behind a license key — the open-source edition is stated to be feature-complete under AGPLv3 [VERIFIED-fetched:https://raw.githubusercontent.com/volcengine/OpenViking/main/README.md]

## Notable absences
No access-control model on the open-source edition: the per-user tree is layout only, and team permissions live in the commercial Enterprise SaaS — nothing enforces who may read which `viking://` subtree. No encryption-at-rest mention anywhere. No immutability guarantee: trajectories and extracted memories are mutable working data, debug-oriented rather than audit-grade. Retrieval has no content-policy screening (injected text in resources becomes recallable instruction material with no scan step documented). Skills stored as context entries have no signing/provenance chain. Windows support exists but the Helper console is closed-source-distributed binaries (CDN downloads) with no build recipe.
