# AI Memory — Feature Dossier
Registry: #19 | Category: 02 | Verified: 4,288★, MIT, last push 2026-08-24 (repo-verify.txt 2026-08-24)

Rust memory server giving coding-agent CLIs a shared persistent markdown wiki compiled from lifecycle-hook observations, with cross-agent handoff injection at session start. §C conflict recorded: the sharing model — one cross-agent wiki injected into every connected agent — bypasses kernel mediation and department scoping.

## Feature inventory
- Zero-friction lifecycle-hook capture across ~25 agent clients; bounded sanitized observations (prompts/post-compaction summaries ≤16 KiB, notifications/tool excerpts ≤2 KiB, 16 KiB durable backstop per observation) [VERIFIED-fetched:https://raw.githubusercontent.com/akitaonrails/ai-memory/main/README.md]
- Karpathy-style wiki: pages LLM-consolidated from observations at session-end (or PreCompact / manual `finalize-session`), supersession chains, git-versioned markdown time-travel via `checkpoints`/`restore-page`/raw git log [VERIFIED-fetched:https://raw.githubusercontent.com/akitaonrails/ai-memory/main/README.md]
- Cross-agent handoff injection: next agent's SessionStart hook prepends a typed "where you left off" block (open questions, next steps, session summary) — quit Claude Code, resume in Codex [VERIFIED-fetched:https://raw.githubusercontent.com/akitaonrails/ai-memory/main/README.md]
- Opt-in managed workstreams: `ai-memory run <harness>` transparently resumes one logical workstream across Claude Code/Codex/OpenCode/Pi/Crush/Kimi/Command Code/Kiro v2-v3/OMP/Grok/Antigravity with native per-harness sessions and a portable visible-event ledger with origin-marked packet rejection [VERIFIED-fetched:https://raw.githubusercontent.com/akitaonrails/ai-memory/main/README.md]
- Per-project isolation by construction: `<wiki_root>/<workspace_id>/<project_id>/` UUID layout keyed off `$cwd`; `.ai-memory.toml` ancestor marker overrides workspace/project; linked worktrees share project identity; purge is atomic `rm -rf` + cascade [VERIFIED-fetched:https://raw.githubusercontent.com/akitaonrails/ai-memory/main/README.md]
- Global preferences scope `_global`: standing user/team context unioned into default `memory_query` results as `global_scope_hits`; event capture never writes there [VERIFIED-fetched:https://raw.githubusercontent.com/akitaonrails/ai-memory/main/README.md]
- Hybrid retrieval: SQLite FTS5 fused via RRF with entity-match streams (≤10 canonical nouns per page frontmatter) and graph-neighbor expansion, plus optional vector RRF when an embedder is configured [VERIFIED-fetched:https://raw.githubusercontent.com/akitaonrails/ai-memory/main/README.md]
- Authority-aware ranking: bounded adjustment favoring maintained `_rules/`, `decisions/`, `procedures/`, `gotchas/` pages over episodic session evidence; tier/pinned/canonical/superseded tags contribute without becoming absolute filters [VERIFIED-fetched:https://raw.githubusercontent.com/akitaonrails/ai-memory/main/README.md]
- Untrusted-retrieval doctrine, stated verbatim: retrieved text remains untrusted historical evidence and never gains instruction authority from its namespace, tier, tags, pin, or rank [VERIFIED-fetched:https://raw.githubusercontent.com/akitaonrails/ai-memory/main/README.md]
- Zero-LLM mode: FTS5 + entity + graph search plus rule-based summarisation with no provider at all; LLM/embedding providers strictly opt-in (Anthropic/OpenAI/Gemini/OIDC; embeddings incl. keyless Ollama/LM Studio/vLLM OpenAI-compatible endpoints) [VERIFIED-fetched:https://raw.githubusercontent.com/akitaonrails/ai-memory/main/README.md]
- Retention lifecycle: `expires_at` TTL pages (TTL beats pin), decay sweep hard-delete past TTL, forget-sweep, feedback signals (`helpful`/`not_helpful`/`stale`/`wrong`) tuning salience and flagging lint findings — feedback never deletes, only lowers confidence [VERIFIED-fetched:https://raw.githubusercontent.com/akitaonrails/ai-memory/main/README.md]
- `bootstrap` seeding: git log + README + docs + module headers one-shot-summarised into seed wiki pages for pre-existing projects [VERIFIED-fetched:https://raw.githubusercontent.com/akitaonrails/ai-memory/main/README.md]
- Auto-improvement scheduler: background review of completed sessions proposing wiki edits recorded in a pending-writes audit trail; approved through the normal write path by default or gated behind `require_approval = true`; per-session claims prevent infinite retry [VERIFIED-fetched:https://raw.githubusercontent.com/akitaonrails/ai-memory/main/README.md]
- Curator: no-LLM rule-based maintenance report over cold episodic pages, stale slots, duplicate normalized titles, dangling cross-project links — report-only unless staged for approval [VERIFIED-fetched:https://raw.githubusercontent.com/akitaonrails/ai-memory/main/README.md]
- Thin-client CLI: all subcommands are HTTP clients of the running server (never touch SQLite/wiki directly); server is single source of truth; `finalize-session` posts synthetic session-end hooks [VERIFIED-fetched:https://raw.githubusercontent.com/akitaonrails/ai-memory/main/README.md]
- Security ladder: loopback-only default, unauthenticated non-loopback fails closed (`--allow-insecure-no-auth` as dangerous exception), bearer auth on all surfaces, OIDC device-token hook auth, per-source rate limiting, ALLOWED_HOSTS anti-DNS-rebinding, TLS delegated to reverse-proxy compose templates [VERIFIED-fetched:https://raw.githubusercontent.com/akitaonrails/ai-memory/main/README.md]
- Multi-operator attribution (v0.8): named-user tokens resolving to identity in audit logs/page frontmatter/UI; first user row flips all `/admin/*` to root-only; per-operator memory slots give context-injection isolation explicitly framed as NOT RBAC [VERIFIED-fetched:https://raw.githubusercontent.com/akitaonrails/ai-memory/main/README.md]
- Read-only `/web` browser UI plus `/api/v1` frontend API; `overview` bundles open handoff + briefing + memory health in one call [VERIFIED-fetched:https://raw.githubusercontent.com/akitaonrails/ai-memory/main/README.md]
- Per-repo capture exclusions: nearest-marker `[capture]` `ignore_paths` policy drops matching file-tool events before they reach spool or server [VERIFIED-fetched:https://raw.githubusercontent.com/akitaonrails/ai-memory/main/README.md]

## Compliant re-implementation sketch
- Spec slot: Information-dept **memory service** inside the self-hosted boundary — SQLite(FTS5) + markdown-wiki store with consolidation at worker teardown; no new runtime class (it's infra like SearXNG, not an agent).
- Access model inverted: NO agent holds a bearer to the memory service. Only the kernel reads/writes; workers receive kernel-composed handoff briefs as dispatch input (§16.6) and query through bounded, dept-scoped retrieval (§6.3).
- Scoping: generalize workspace/project UUID isolation into department scope keys — every page carries its owning dept; cross-dept reads denied by default, `_global` reserved for owner-level preferences.
- Adopt the untrusted-retrieval doctrine verbatim: rank/tier/tags affect provenance only; retrieved memory never authorizes instructions. Pair with the §16.6 injection scan on everything memory returns.
- Capture: keep hook ingestion but invert defaults — deny-by-default capture allow-lists per scope (its `[capture] ignore_paths` marker proves the mechanism), sizes clamped at the adopted 16 KiB/2 KiB bounds.
- Retention: adopt the whole lifecycle — consolidation at teardown, `expires_at` TTL beating pins, decay/forget sweeps, helpful/stale feedback tuning salience, curator lint — scheduled by kernel ticks/§14.6 re-checks, never a resident scheduler daemon.
- Growth gating: auto-improvement proposals always land in a pending-writes queue requiring human approval before they enter dept memory (drop the approve-immediately default).
- Stay out: managed cross-harness launcher (wrapped-CLI exclusion), multi-operator OIDC ladder (single-owner), LAN/cloud binding recipes (loopback-only behind the kernel), public `/web` binding (owner console renders locally instead).

## Notable absences

> SKEPTIC FIX: the compliant sketch's memory service is a KERNEL-EMBEDDED store inside the Information department (in-process, like §6.3's SQLite access layer) — never a separately-installed resident service process.
No content-policy gate on what enters memory beyond size bounding and path exclusions — sanitization is claimed but not specified as injectable-content screening. No encryption at rest for wiki/DB. No per-page ACL by design ("no per-page RBAC") — isolation is whole-project, insufficient once scopes mean departments. No decision-log immutability guarantee (git history is mutable force-push territory; supersession chains mitigate, don't prevent). No staleness anchoring to code revisions (explicitly separates itself from live code intelligence rather than validating claims against it).
