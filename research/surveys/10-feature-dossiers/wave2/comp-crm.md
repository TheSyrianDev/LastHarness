# Comp AI CRM (trycompai/crm) — Feature Dossier
Registry: #114 | Category: 06 | Verified: 8,866 stars, MIT, last push 2026-08-21

## Feature inventory
- **Evidence-ledger design — no confidence scores**: "nothing about a person is guessed. No tool accepts a confidence score, because a model asked to grade its own certainty will, and it will be wrong in the direction that makes it look useful." Tools instead report typed observations (`crm.signature-block`, `github.account-identity`) and "a ledger prices the evidence" [VERIFIED-fetched:https://raw.githubusercontent.com/trycompai/crm/main/README.md]
- Evidence-ledger mechanics as documented: findings carry what-was-observed provenance rather than self-graded certainty; the ledger prices each item; strong evidence writes directly to the record; weak evidence becomes a suggestion a human settles; blank field deliberately preferred over confidently wrong fact ("nobody can tell it is wrong") [VERIFIED-fetched:https://raw.githubusercontent.com/trycompai/crm/main/README.md]
- Agentic-first inversion: "the agent is not a feature of the CRM; the CRM is where the agent keeps its notes" — own deployment, own schedule, own work queue, research budget it spends until exhausted; non-request/response, keeps running with browser closed [VERIFIED-fetched:https://raw.githubusercontent.com/trycompai/crm/main/README.md]
- Durable agent on eve framework: tools are files, skills are markdown files versioned like code (4 skills: `evidence.md`, `identity-matching.md`, `data-boundaries.md`, `writing-a-brief.md`), 18 authored tools (`read_crm_history`, `search_crm`, `identify_contact`, `research_person`, `enrich_company`, `record_fact`, `schedule_recheck`…), sessions survive redeploys and resume mid-work [VERIFIED-fetched:https://raw.githubusercontent.com/trycompai/crm/main/README.md]
- Work-queue leasing: `lib/tasks.ts` `claimDue` leases rows `FOR UPDATE SKIP LOCKED` so two dispatchers take disjoint work; dead runs free their row at lease expiry; due-times live in task rows not cron expressions; `schedule_recheck` requires a stated reason that is shown to the rep ("an agent that cannot say why it will be back in fourteen days does not have a reason, it has a default") [VERIFIED-fetched:https://raw.githubusercontent.com/trycompai/crm/main/README.md]
- Deny-all egress sandbox: bash/grep/glob + `/workspace` with **no network and no database**; sandbox never receives `DATABASE_URL`; `web_fetch` runs in app runtime and `web_search` at the model provider — removes "the only path by which a customer's email body could leave through a shell command" [VERIFIED-fetched:https://raw.githubusercontent.com/trycompai/crm/main/README.md]
- Zero-vendor operation: fully functional with no external API keys — `read_crm_history` mines your own threads/meetings/signature blocks ("no data vendor can sell you a reply from the person's own address"); agent is told at session start which sources this install has and plans around them, printing on/off state per source [VERIFIED-fetched:https://raw.githubusercontent.com/trycompai/crm/main/README.md]
- Per-record Agent tab observability: watch steps as taken including leads discarded and why; ask questions in place when the agent cannot decide between two people; durable conversations carried in a signed token (`AGENT_BRIDGE_SECRET`) [VERIFIED-fetched:https://raw.githubusercontent.com/trycompai/crm/main/README.md]
- Deny-by-default auth: `ALLOWED_SIGN_IN` is the entire authorization model — unset means nobody can sign in ("the safe direction to fail"); accepts domains, addresses, or mix; Better Auth with Google/Microsoft/own IdP [VERIFIED-fetched:https://raw.githubusercontent.com/trycompai/crm/main/README.md]
- Read-only forward-only mailbox sync: Microsoft `Mail.Read` only (can never send/reply/move/delete); first check records a watermark and imports nothing, so connecting an old mailbox doesn't dump years of mail; sync route guarded by `CRON_SECRET` [VERIFIED-fetched:https://raw.githubusercontent.com/trycompai/crm/main/README.md]
- Architecture rules: intelligence never lives in the API (Nest reports events, agent decides meaning — two identity matchers drifted when duplicated), `packages/ui` sole UI source, deliberately single-tenant with no organizations column ("a column, an index and a permissions check that buys nothing") [VERIFIED-fetched:https://raw.githubusercontent.com/trycompai/crm/main/README.md]
- Stack: Bun/Turborepo monorepo deployed Vercel-first (eve runtime, Vercel AI Gateway, Vercel Sandbox in production, Neon Postgres, Upstash Redis, Vercel Blob) with local fallbacks (Docker Compose Postgres, Docker or microsandbox for the sandbox locally) [VERIFIED-fetched:https://raw.githubusercontent.com/trycompai/crm/main/README.md]

## Per-feature verdict

| Evidence ledger (typed observations, priced evidence, strong→write / weak→human suggestion, no confidence scores) | 🧩 | §12 decision-log philosophy + §10.2 evidence weighting | The flagship pattern. It solves exactly what §12's immutable log wants: findings are records of *what was observed* (auditable, replayable), never self-graded certainty (which biases toward looking-useful). The three-threshold behavior — write / suggest-for-human / prefer-blank — is a ready-made policy spec for how agents append to LastHarness's decision log. |
| CRM-as-agent-memory inversion | 🏛 | Sales/Relations dept candidate | A whole business function (contacts/companies/deals + autonomous research) with the agent as primary writer. No existing department owns external-relationship records — strongest wave-2 new-dept candidate alongside Media Production. |
| Work-queue leasing (`FOR UPDATE SKIP LOCKED`, lease expiry, dueAt rows, reasoned rechecks) | 🧩 | §16.5 ephemeral worker dispatch + §4.4 kernel mediation | Crash-safe disjoint leasing is precisely how kernel-mediated dispatch should hand ephemeral workers their queues; mandatory stated-reason rechecks double as decision-log entries. |
| Deny-all-egress sandbox without DB credentials | 🧩 | §7.1 default-deny egress + §16.6 allow-lists at dispatch | Independent implementation of LastHarness's exact invariant pair: shell access granted *because* network+credentials are withheld; fetch delegated to runtimes that log. ## Notable absences
No team roles/permissions beyond one flat allow-list (deliberate single tenant); no import/export or migration tooling documented; no backup/retention policy; no evaluation suite for identity-matching accuracy (drift war story told, no test contract published); telemetry present with opt-out env rather than opt-in; deployment docs assume Vercel — self-host guidance covers Postgres compose only; no mobile or offline client.
