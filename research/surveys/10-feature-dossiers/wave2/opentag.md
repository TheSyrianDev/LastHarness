# OpenTag — Feature Dossier
Registry: #105 | Category: 07 | Verified: 1,114 stars, MIT, last push 2026-08-21

SCOPE: CopilotKit Channels SDK starter — a self-hosted knowledge-work agent for Slack/Microsoft Teams (LangGraph deep agent + AG-UI), built to be forked. Evaluated for the messaging-surface and approval-gate patterns, not as a deployable LastHarness component.

## Feature inventory
- Channels SDK starter assembling: managed Channel, Node runtime, Python LangGraph agent, connected tools, native Slack UI — "production shape, not demo shape" with pinned `@copilotkit/channels` + `@copilotkit/runtime` versions [VERIFIED-fetched:https://raw.githubusercontent.com/CopilotKit/OpenTag/main/README.md]
- Topology: Slack/Teams → HTTPS to Intelligence-hosted Request URL → **outbound websocket opened by your runtime** → Node CopilotRuntime with embedded Channels → AG-UI over HTTP → Python LangGraph agent (deepagents) calling OpenAI/Tavily/GitHub-MCP/PostHog-MCP/Linear-MCP/Notion-MCP; no Socket Mode, no tunnel, no public URL of your own [VERIFIED-fetched:https://raw.githubusercontent.com/CopilotKit/OpenTag/main/README.md]
- Two channel-runner modes: managed **CopilotKit Intelligence** channel (holds Slack/Teams platform credentials; handles delivery/state/concurrency) or your own runner from the open-source Channels SDK — quick start uses managed [VERIFIED-fetched:https://raw.githubusercontent.com/CopilotKit/OpenTag/main/README.md]
- Approval gate before writes: a code interceptor wraps every Linear/Notion mutation **before the MCP request runs**, emitting a LangGraph interrupt + resumable `confirm_write` card; reads and rendering never pause; Daytona coding-subagent push + draft-PR uses the same card [VERIFIED-fetched:https://raw.githubusercontent.com/CopilotKit/OpenTag/main/README.md]
- Credential-present source registration: Tavily, GitHub (read-only PAT), PostHog (read-only), Linear, Notion tools register **only when their env credentials exist** — "setting only one disables it" for Notion's pair [VERIFIED-fetched:https://raw.githubusercontent.com/CopilotKit/OpenTag/main/README.md]
- Trigger rules: a mention subscribes the thread; unmentioned messages run the agent only in already-subscribed threads; unmentioned message in a fresh conversation must produce **silence** — codified as verification check #3 [VERIFIED-fetched:https://raw.githubusercontent.com/CopilotKit/OpenTag/main/README.md]
- Claim-based managed delivery hazard: two runtimes declaring the same Channel name in one project race per delivery and "the loser silently receives nothing"; forks must take their own project/key/name [VERIFIED-fetched:https://raw.githubusercontent.com/CopilotKit/OpenTag/main/README.md]
- Generative UI from files: issue cards, tables, charts, diagrams under `app/components`/`app/tools`; entire Channel surface in one file `app/channel.tsx`; CSV-in → native Slack chart + takeaway demo [VERIFIED-fetched:https://raw.githubusercontent.com/CopilotKit/OpenTag/main/README.md]
- Fork-first customization contract: persona (`agent/prompts/system.py`), agent swap via `AGENT_URL` to **any AG-UI-compatible agent** without touching Channel lifecycle, tools per file, write-gate in `agent/write_confirmation.py`, topology as code in `.railway/railway.ts` [VERIFIED-fetched:https://raw.githubusercontent.com/CopilotKit/OpenTag/main/README.md]
- Deployment shapes: Railway two services (agent `uvicorn :8123` health `/health`; runtime `pnpm runtime` health `/api/copilotkit/info`) over private networking, or AWS ECS Fargate private task + Secrets Manager; ghcr images; graceful idempotent shutdown for Channels/HTTP/rendering browser [VERIFIED-fetched:https://raw.githubusercontent.com/CopilotKit/OpenTag/main/README.md]
- Diagnostics: `channels status --json` reporting declaration/source/server/adapter/environment/lifecycle states; lifecycle breadcrumbs at warn level with debug guidance; three-check proof protocol (mention / follow-up / expected silence) [VERIFIED-fetched:https://raw.githubusercontent.com/CopilotKit/OpenTag/main/README.md]
- Coding-agent onboarding skill `channels-setup`: installs a skill that fetches its workflow live from copilotkit.ai/channels-guide.md so it can't go stale; hands secrets back to user, never through chat; noted flaw — installs into every detected coding agent with no way to narrow [VERIFIED-fetched:https://raw.githubusercontent.com/CopilotKit/OpenTag/main/README.md]

## Per-feature verdict
| Feature | Type | LastHarness landing | Rationale |
|---|---|---|---|
| Managed CopilotKit Intelligence channel | ❌ | — | Platform credentials, ingress, delivery state, and concurrency live on a third-party cloud — execution mediation outside the boundary violates kernel-mediated routing + default-deny egress regardless of where the runtime runs. |
| Long-running resident Node channels runtime | ❌ | §16.5 ephemeral dispatch | A persistent websocket-holding process waiting for mentions is a standing process; sanctioned shape is scheduled/re-triggered dispatches (§14.6) rehydrating context, not an always-on listener. |
| `confirm_write` resumable-interrupt approval gate before mutations | 🧩 | §16.10 Owner Surfaces approval-gate contract | The gem: write-pauses-execution with a resumable typed card, interceptor enforced in code *before* the side-effecting call, reads exempted. Direct design input to LastHarness's typed confirmation gates. |
| Credential-present tool registration (absent creds = tool absent) | 🧩 | §4.4 + §14.5 allow-list provisioning | Tools appearing only when credentialed-and-vetted is deny-by-default made physical; pairs with LastHarness's gated memory/tool grants per department. |
| AG-UI-over-HTTP decoupling of channel runtime from agent | 🧩 | §4.4 kernel-mediated routing shape | Any-agent swap behind a stable protocol boundary proves the routing layer can be policy-owned while engines change — the same inversion LastHarness's kernel makes mandatory. |
| Mention-subscribes-thread trigger rules w/ expected-silence check | 🧩 | §14.6 notification/noise policy | Explicit default-deny for agent attention (silence unless subscribed) plus a test asserting it — adopt verbatim for any owner-facing messaging surface. |
| Claim-based name-collision silent-loss behavior | ⚙ | §12/§16.5 delivery-accounting cautionary pattern | Proof that named delivery queues need ownership registration and loss detection; LastHarness's decision log must record claim/delivery outcomes, never fail silently. |
| Generative UI cards/charts from structured outputs | ⚙ | §16.6 Output surfaces / owner console | Presentation-layer rendering of worker results; harmless and useful once data comes from sanctioned dispatch outputs. |
| Railway/Fargate two-service topology-as-code | 🧩 | §16.1 deployment hygiene | Declarative service topology with pinned deps and graceful shutdown is good hygiene, but only relevant if a resident runtime were ever justified — currently it is not. |
| Live-fetched setup skill (anti-staleness pointer pattern) | 🧩 | §14.5 skill intake — with caveat | Fetching workflow docs at run time defeats version pinning; LastHarness intake requires pinned snapshots. The secret-handling discipline (never paste secrets in chat) transfers. |
| Skill auto-installs to every detected coding agent | ❌ | §14.5 intake blast-radius control | Documented inability to narrow install targets is the opposite of deny-by-default provisioning; cited as an anti-pattern. |

## Notable absences
No self-contained ingress path: even the "own channel runner" mode still requires Slack/Teams platform credentials and outbound websockets from a resident process — there is no pull/poll-based ephemeral alternative documented. No memory layer between threads (state is delegated to the managed cloud). No audit log of approvals/writes beyond LangGraph interrupts; no rate-limiting or sender-authentication model beyond Slack signing secrets held by the managed service. Windows/Linux desktop concerns out of scope by design. Discord/Telegram/WhatsApp adapters listed as coming soon.
