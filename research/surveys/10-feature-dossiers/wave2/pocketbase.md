# PocketBase (pocketbase/pocketbase) — Feature Dossier
Registry: #130 | Category: 08 | Verified: 60,786 stars, MIT, last push 2026-08-23

## Feature inventory
- **What "one file" actually contains**: a single Go backend executable bundling — embedded database (SQLite) with realtime subscriptions, built-in files and users management, a convenient Admin dashboard UI, and a simple REST-ish API [VERIFIED-fetched:https://raw.githubusercontent.com/pocketbase/pocketbase/master/README.md]
- **Standalone executables are themselves minimal Go programs**: the prebuilt release binaries are built from the `examples/base/main.go` file and come with the JS VM plugin enabled by default, allowing extension with JavaScript [VERIFIED-fetched:https://raw.githubusercontent.com/pocketbase/pocketbase/master/README.md]
- **Go embed/toolkit model**: distributed as a regular Go library — "build your own custom app specific business logic and still have a single portable executable at the end"; `CGO_ENABLED=0 go build` yields statically linked binaries on a pure-Go SQLite driver across ~20 GOOS/GOARCH build targets including linux amd64/arm64 [VERIFIED-fetched:https://raw.githubusercontent.com/pocketbase/pocketbase/master/README.md]
- **Deployment shape = one binary + three directories**: app directory is `pocketbase · pb_migrations/ · pb_hooks/ · pb_data/`; deploy by rsync-ing that directory and running `./pocketbase serve yourdomain.com` (passing a domain auto-manages Let's Encrypt TLS); optional systemd unit documented; first superuser created via `superuser create EMAIL PASS`; reverse-proxy guidance includes real-client-IP header settings; community Dockerfile mounts `/pb/pb_data` as the persistence volume [VERIFIED-fetched:https://pocketbase.io/docs/going-to-production]
- **Backup/restore story**: manual path is copy/replace `pb_data` with the application stopped (transactional safety); v0.16+ builtin Dashboard backup/restore APIs produce a full ZIP snapshot of `pb_data` INCLUDING locally stored uploaded files (excluding prior backups and S3-offloaded files); backups store locally or to S3-compatible storage; for large `pb_data` (5GB+) the official guidance escalates to a `sqlite3 .backup` + rsync script instead of the built-in snapshot [VERIFIED-fetched:https://pocketbase.io/docs/going-to-production]
- **Migrations live beside the binary** as `pb_migrations/` (Go and JS migration frameworks both documented) — schema evolution ships as files in the app directory applied by the same executable [VERIFIED-fetched:https://pocketbase.io/docs/going-to-production]
- **Hardening recommendations**: builtin rate limiter (v0.23+); superuser IPs whitelist (v0.38+) returning 403 even when an attacker holds a valid superuser token; optional MFA/OTP enforcement for `_superusers` auth (manual OTP generation console command as fallback); optional settings encryption via `PB_ENCRYPTION_KEY` + `--encryptionEnv` because SMTP/S3 credentials otherwise sit as plain JSON in the database; GOMEMLIMIT and open-file-descriptor tuning notes; SMTP over internal sendmail [VERIFIED-fetched:https://pocketbase.io/docs/going-to-production]
- **Pre-1.0 honesty + contribution freeze**: "full backward compatibility is not guaranteed before reaching v1.0.0"; PRs temporarily restricted to existing collaborators due to LLM spam ("LLM contributions are not welcome"), issues/discussions remain open [VERIFIED-fetched:https://raw.githubusercontent.com/pocketbase/pocketbase/master/README.md]

## Per-feature verdict
| Feature | Type | LastHarness landing | Rationale |
|---|---|---|---|
| Single-artifact embedding (SQLite + auth + files + admin UI + REST API in ONE executable) | 🧩 | Kernel packaging target for the Linux-env boundary | Deployment-shape reference, not adoption: LastHarness's kernel is Python+SQLite directly, so adopting PocketBase would insert a second language runtime, a second SQLite instance, and a parallel auth/admin stack next to what the kernel already implements. Its value is the existence proof that a full backend compresses into one portable artifact — the shape LastHarness's dept tool packs should imitate. |
| Toolkit/embed model (library first; custom logic compiles INTO the artifact) | 🧩 | §16 worker/pack assembly | Inverts the plugin default: extension happens in code you own, built into the binary rather than loaded at runtime — matches LastHarness's no-standing-process, no-dynamic-runtime instincts. |
| Binary + pb_migrations + pb_hooks + pb_data directory contract | 🧩 | Dept-tool deployment spec | State (`pb_data`) strictly separated from logic (binary) and schema history (`pb_migrations`) gives each dept tool a clean unit-of-backup and restore boundary. |
| Two-tier backup semantics (convenient ZIP snapshot vs `sqlite3 .backup` escalation ≥5GB) | 🧩 | §12 log durability | Snapshot-with-uploads for small data, engine-consistent dump for large data is directly reusable policy for decision-log + attached-artifact backups. |
| Migrations-as-files beside the executable | 🧩 | Schema-evolution for kernel stores | Versioned schema history as reviewable files in the app directory fits LastHarness's config-as-code review flow. |
| Superuser IP whitelist + MFA/OTP + settings encryption | ⚙ | Security §14.7 hardening checklist | Stolen-token containment (valid token still gets 403 off-whitelist), out-of-band OTP, secrets-at-rest encryption — adopt as the baseline for any admin surface LastHarness exposes. |
| Builtin rate limiter | ⚙ | Security, §7.1 adjacent | API-edge abuse containment; cheap pattern worth mirroring on kernel-exposed HTTP surfaces. |
| Realtime subscriptions over embedded SQLite | 🧩 | §16.10 Owner Surfaces | Live record-change push is the right feed shape for owner-console views; in LastHarness it would be kernel-mediated event fan-out, never peer channels. |
| Event-hook bindings via embedded JS VM (default-on in prebuilt binaries) | ❌ | — | A second scripting runtime embedded inside the service process; the LastHarness kernel stays Python-only. The hook-registration PATTERN transfers; the JS VM does not. |
| S3-compatible backup storage option | ❌ | — | Replicates boundary data to third-party cloud storage; local-first plus default-deny egress forbids it as-shipped. |

## Notable absences
Author-acknowledged pre-v1.0 compatibility instability. No horizontal scaling story — deliberately one server ("PocketBase applications live entirely on a single server"). No granular roles beyond users vs `_superusers` collections. No official Docker image (community Dockerfile only). No audit journal of admin/settings changes — settings sit in the DB optionally encrypted, but modifications are not logged as decisions. LLM-spam PR freeze slows external contribution cadence until further notice.
