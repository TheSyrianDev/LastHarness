# Semantica — Feature Dossier
Registry: #72 | Category: 02 | Verified: 10,590★, MIT, last push 2026-08-24 (repo-verify.txt 2026-08-24)

Graph-native context and accountable-AI infrastructure ("open-source Palantir"): knowledge-graph construction with W3C PROV-O provenance on every fact and first-class decision records — the strongest §12.4 decision-intelligence / §14.5 Knowledge-Base schema candidate in either wave. Core is deterministic (no LLM needed for graph build, reasoning, or provenance) and its provenance store is SQLite.

## Feature inventory
- Decisions as first-class graph nodes: `record_decision(category, scenario, reasoning, outcome, confidence, metadata)` stores a permanent structured record; framed as answering "what did your AI decide, why, and what happened next?" for regulators [VERIFIED-fetched:https://raw.githubusercontent.com/semantica-agi/semantica/main/README.md]
- Causal edge schema over decisions: `add_causal_relationship(a, b, relationship_type)` restricted to CAUSED / INFLUENCED / PRECEDENT_FOR; queries: `trace_decision_chain` (full causal ancestry), `find_similar_decisions` (semantic precedent search), `analyze_decision_impact` (downstream influence map), `check_decision_rules` (policy compliance gate vs configurable rule sets), `get_decision_insights` [VERIFIED-fetched:https://raw.githubusercontent.com/semantica-agi/semantica/main/README.md]
- W3C PROV-O lineage on every fact AND relationship: `track_entity(entity_id, source="ehr/medication_orders_2024.json", metadata={page, confidence, extractor})`, `track_relationship(relationship_id, source, metadata={source_entity_id, target_entity_id})`; retrieval via `get_lineage` / `trace_lineage` (full ancestor chain); persisted to a SQLite file (`storage_path="./provenance.db"`); exportable as PROV-O/RDF turtle for regulator submission [VERIFIED-fetched:https://raw.githubusercontent.com/semantica-agi/semantica/main/README.md]
- Deterministic core: graph construction, reasoning engines (forward chaining, Rete network, recursive Datalog, SPARQL), and provenance run with NO LLM; explanation generator returns conclusion + step list + justification; maintainers caveat their own Rete alpha-node matcher as intentionally simple — validate before production gating [VERIFIED-fetched:https://raw.githubusercontent.com/semantica-agi/semantica/main/README.md]
- Ontology governance: OWL generation from data, SHACL shape validation (valid/consistent/satisfiable report), SKOS vocabulary management with visual editor [VERIFIED-fetched:https://raw.githubusercontent.com/semantica-agi/semantica/main/README.md]
- Conflict detection across sources (value/type/relationship/temporal/logical conflicts, severity-ranked) with resolution strategies credibility_weighted / most_recent / voting; SourceTracker registers per-source credibility scores [VERIFIED-fetched:https://raw.githubusercontent.com/semantica-agi/semantica/main/README.md]
- Entity resolution at scale: blocking + semantic clustering dedup with provenance-preserving merges and merge history [VERIFIED-fetched:https://raw.githubusercontent.com/semantica-agi/semantica/main/README.md]
- Bi-temporal facts: valid time (when true in the world) tracked independently from recorded_at (when learned); typed edges carry valid_from/valid_until; point-in-time snapshots via `state_at(date)` replay history without reprocessing; Allen interval algebra + natural-language temporal normalization [VERIFIED-fetched:https://raw.githubusercontent.com/semantica-agi/semantica/main/README.md]
- Polyglot swappable storage: RDF triple stores (embedded Oxigraph by default, Blazegraph, Apache Jena, Eclipse RDF4J) and Labeled Property Graphs (Neo4j, FalkorDB, Apache AGE, AWS Neptune) plus vector stores (FAISS, sqlite, inmemory, Qdrant, Milvus, PgVector…) — backend swap without code change [VERIFIED-fetched:https://raw.githubusercontent.com/semantica-agi/semantica/main/README.md]
- Pipeline DSL: declarative ingest→extract→build→deduplicate→export steps with parallelism control and progress/status introspection [VERIFIED-fetched:https://raw.githubusercontent.com/semantica-agi/semantica/main/README.md]
- Delivery surfaces: REST API, full MCP server, comprehensive CLI (`semantica doctor` install verification), interactive visualization workbench (force-directed graphs, ontology hierarchy, temporal timeline scrubber) [VERIFIED-fetched:https://raw.githubusercontent.com/semantica-agi/semantica/main/README.md]
- Multi-agent shared context: Agno integration binds every agent on a team to ONE shared context graph + decision kit — "researcher's findings instantly available to the analyst, no copy, no sync" [VERIFIED-fetched:https://raw.githubusercontent.com/semantica-agi/semantica/main/README.md]
- Ingestion breadth: files/web/DBs/Git/email/Kafka/GDrive plus enterprise lakehouse connectors (Databricks Unity Catalog w/ lineage introspection, Snowflake key-pair/OAuth) [VERIFIED-fetched:https://raw.githubusercontent.com/semantica-agi/semantica/main/README.md]

## Notable absences
No immutability mechanism: decision nodes and provenance rows live in mutable graphs/SQLite with point-in-time snapshots as the only history defense — LastHarness's append-only/WORM discipline would have to be layered on top. No encryption-at-rest mention for provenance.db or graph stores. No access-control model at all (no users, scopes, or ACLs — governance means ontology shapes, not permissions). Multi-writer concurrency semantics undocumented. Maintainer-flagged simplicity of the Rete matcher (their own production warning). The breadth of ingest connectors widens supply-chain surface substantially relative to what a single-owner deployment would ever enable.
