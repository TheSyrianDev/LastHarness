# Sandcastle — Feature Dossier
Registry: #7 | Category: 06 | Verified: 7,609★, MIT, last push 2026-06-29 (repo-verify.txt 2026-08-24)

TypeScript library for orchestrating AI coding agents in isolated sandboxes via a single `sandcastle.run()` call: sandboxing handled by pluggable providers, agent commits merged back via configurable branch strategy. §C conflict recorded: provider-abstracted sandboxing over Docker/Podman/Vercel backends.

## Feature inventory
- One-call programmatic agent runs: `run({agent, sandbox, prompt})` returning per-iteration results, matched completion signal, `commits[{sha}]`, and target branch [VERIFIED-fetched:https://raw.githubusercontent.com/mattpocock/sandcastle/main/README.md]
- Sandbox-provider abstraction: Docker and Podman bind-mount providers, Vercel provider (cloud Firecracker microVMs via `@vercel/sandbox`), `noSandbox()` host-direct mode; custom providers via `createBindMountSandboxProvider` / `createIsolatedSandboxProvider` [VERIFIED-fetched:https://raw.githubusercontent.com/mattpocock/sandcastle/main/README.md]
- Branch strategies controlling how agent changes relate to git: `head` (write-through to working dir), `merge-to-head` (temp branch in a worktree, merged back, cleaned up), named-branch worktree with reuse and safe fast-forward from origin (ADR 0003) [VERIFIED-fetched:https://raw.githubusercontent.com/mattpocock/sandcastle/main/README.md]
- First-class worktree lifecycle: `createWorktree()` independent of any sandbox; interactive session then AFK hand-off on the same worktree; split ownership (`sandbox.close()` tears down container only, `wt.close()` owns worktree); dirty worktrees preserved on close [VERIFIED-fetched:https://raw.githubusercontent.com/mattpocock/sandcastle/main/README.md]
- Reusable warm sandbox: `createSandbox()` runs multiple agents/rounds in one container with deps persisting; `sandbox.exec()` shell commands between runs for verify-before-proceed gating; `await using` auto-teardown [VERIFIED-fetched:https://raw.githubusercontent.com/mattpocock/sandcastle/main/README.md]
- Iteration-loop controls: `maxIterations`, `completionSignal` string(s) for early stop (default `<promise>COMPLETE</promise>`), `idleTimeoutSeconds` resetting on output, `completionTimeoutSeconds` grace window resolving hung-process runs successfully with warning (ADR 0019) [VERIFIED-fetched:https://raw.githubusercontent.com/mattpocock/sandcastle/main/README.md]
- AbortSignal cancellation: kills the in-flight agent subprocess, preserves the worktree, rejects with signal reason [VERIFIED-fetched:https://raw.githubusercontent.com/mattpocock/sandcastle/main/README.md]
- Prompt system: `promptFile` vs mutually-exclusive inline prompt; `{{KEY}}` `promptArgs` substitution resolved host-side before expansion; `` !`command` `` dynamic-context expressions executed inside the sandbox after `onSandboxReady`; built-in non-overridable `{{SOURCE_BRANCH}}`/`{{TARGET_BRANCH}}` args; user-authored arg values treated as inert text [VERIFIED-fetched:https://raw.githubusercontent.com/mattpocock/sandcastle/main/README.md]
- Structured output extraction: `Output.object()`/`Output.string()` parse XML-tagged stdout payloads validated against Standard Schema validators (Zod/Valibot/ArkType); `maxRetries` drives a session-resume repair loop feeding back validation errors [VERIFIED-fetched:https://raw.githubusercontent.com/mattpocock/sandcastle/main/README.md]
- Session resume/fork: `resumeSession` option plus `result.resume()`/`result.fork()` continuing a captured session for one iteration in the same warm sandbox, fork leaving the parent intact (ADR 0018) [VERIFIED-fetched:https://raw.githubusercontent.com/mattpocock/sandcastle/main/README.md]
- Lifecycle hooks split by execution site — `host.*` (`onWorktreeReady`) and `sandbox.*` (`onSandboxReady`) — plus `copyToWorktree` staging of host files into the sandbox [VERIFIED-fetched:https://raw.githubusercontent.com/mattpocock/sandcastle/main/README.md]
- Observability: file/stdout logging modes; `onAgentStreamEvent` forwarding `{type: text|toolCall|raw, iteration, timestamp}` chunks to external systems with broken-forwarder isolation; verbose raw-stdout capture [VERIFIED-fetched:https://raw.githubusercontent.com/mattpocock/sandcastle/main/README.md]
- `sandcastle init` CLI: scaffolds `.sandcastle/`, builds the container image (Dockerfile or Containerfile), detects package manager, fully flag-driven non-interactive mode; five templates (blank, simple-loop, sequential-reviewer, parallel-planner, parallel-planner-with-review) [VERIFIED-fetched:https://raw.githubusercontent.com/mattpocock/sandcastle/main/README.md]
- Agent providers: `claudeCode`, `codex`, `pi`, `cursor`, `opencode`, `copilot` with per-provider options (e.g. effort level); resume-capability matrix enforced at runtime (structured-output retries throw on non-resumable providers) [VERIFIED-fetched:https://raw.githubusercontent.com/mattpocock/sandcastle/main/README.md]
- Docker provider hardening knobs: readonly/tilde-relative mounts, SELinux `z`/`Z` volume labels, container network attach, `--group-add`, `--device` passthrough, `--cpus` limits, containerUid/GID pre-flight mismatch check [VERIFIED-fetched:https://raw.githubusercontent.com/mattpocock/sandcastle/main/README.md]

## Compliant re-implementation sketch
- Spec slot: extend §16.6 with a **batch-run descriptor** — `{promptFile, promptArgs, maxIterations, completionSignal, outputSchema}` — the kernel compiles into one ephemeral Claude Agent SDK worker dispatch; no library, no tsx host script.
- Host: Development dept manager composes descriptors; kernel spawns the worker inside THE single self-hosted Linux env; parallelism is the already-spec'd worktree fan-out (§16.1/§7.1), not containers.
- Isolation: replace all sandbox providers with the existing boundary — deny-by-default tool allow-lists + worktree-scoped writes; the `noSandbox()` lesson is that isolation policy, not a container, is what matters.
- Keep branch strategies as worker-contract options (head / merge-to-head / named branch with reuse+fast-forward) and collect `commits[{sha}]` into the dispatch result for review.
- Keep termination mechanics verbatim: maxIterations cap, owner-chosen completion signals, output-reset idle timeout, and the completion-grace window that succeeds a run whose child processes hang.
- Keep structured-output extraction: XML-tagged payload validated against a Standard Schema, with a bounded (§10.2-capped) resume-and-repair loop on validation failure.
- Map `host.*`/`sandbox.*` hooks to pre-spawn/post-ready dispatch hooks; `copyToWorktree` becomes kernel-side worktree staging before the worker starts.
- Stay out: Vercel backend, container images/init scaffolding, multi-CLI provider adapters, warm reusable sandboxes — each named invariant violation above; the compliant substrate is ephemeral SDK workers on kernel-managed worktrees.

## Notable absences
No approval/HITL gate mid-run — the only human controls are abort and pre-set limits; nothing like LastHarness's approvals queue for destructive ops or spend. No memory or cross-run knowledge beyond session resume ids. No egress policy inside the sandbox — network attach is connect-only configuration with no filtering documented. No telemetry aggregation beyond the stream-event callback (no spans, costs, or durable log). No onboarding path for non-technical operators (assumes git, npm, tsx fluency).
