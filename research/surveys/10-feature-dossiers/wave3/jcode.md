Skip-confirmation dossier. Recorded disposition: "jcode removal recorded §16 header" (09-feature-extraction.md #76) — docs/archive/lastharness-v1-spec.md §16 states "jcode is no longer part of the architecture… no wrapped external CLI and no black-box tool worker category," and §16.5 records that jcode's `swarm` mode was excluded for peer-to-peer coordination with no central policy authority. This dossier CONFIRMS both from the README and examines the memory-graph feature against LastHarness's department-scoped gated memory (§6) rather than any code_index harvest.

## Feature inventory
- **RAM-efficiency positioning**: "The most RAM efficient harness"; self-published PSS comparisons claim 27.8 MB single-session / ~10 MB per added session vs Claude Code at 386.6 MB / ~213 MB, plus 14 ms time-to-first-frame; Rust TUI with custom scrollback and a from-scratch terminal emulator (handterm) in progress [VERIFIED-fetched:https://raw.githubusercontent.com/1jehuang/jcode/master/README.md]
- **Memory graph (agent memory)**: every turn/response embedded as a semantic vector; each turn queries a graph of memories via cosine similarity and hits are injected into the conversation automatically (or via a memory sideagent that verifies relevance before injection); extraction runs on triggers ("semantic drift, K turns since last extraction, session end") by a memory sideagent writing into the graph; ambient mode periodically consolidates — reorganizes, checks staleness and conflicts; explicit memory tools for active search/store plus session search as traditional RAG [VERIFIED-fetched:https://raw.githubusercontent.com/1jehuang/jcode/master/README.md]
- **Swarm mode (recorded exclusion)**: spawn two or more agents in one repo and "the server" manages them for native collaboration — agent A editing a file agent B read triggers a server notification to B; agents DM one agent, broadcast to all server-hosted agents, or repo-scoped groups; agents can autonomously spawn their own swarms ("turns the main agent into a coordinator and the spawned agents into workers"), headed or headless [VERIFIED-fetched:https://raw.githubusercontent.com/1jehuang/jcode/master/README.md]
- **Persistent background server**: `jcode serve` / `jcode connect` runs a persistent server process clients attach to; iOS app planned to reach "your personal machine's environment from your phone, via Tailscale" [VERIFIED-fetched:https://raw.githubusercontent.com/1jehuang/jcode/master/README.md]
- **Self-dev mode**: the agent enters its own source code, edits/builds/tests it, reloads its own binary, and continues across live sessions "fully automatically"; frontier model recommended because weak models make breaking changes [VERIFIED-fetched:https://raw.githubusercontent.com/1jehuang/jcode/master/README.md]
- **Provider/OAuth breadth + local runtimes**: subscription OAuth flows for Claude/OpenAI/Gemini/Copilot/Azure and ~30 aggregator profiles; built-in `ollama` and `lmstudio` profiles speaking OpenAI-compatible endpoints; named-profile config supports `anthropic-compatible` gateways with bearer/custom-header auth; `ANTHROPIC_BASE_URL` override honored [VERIFIED-fetched:https://raw.githubusercontent.com/1jehuang/jcode/master/README.md]
- **Browser tool**: first-class built-in `browser` tool (open/snapshot/click/fill_form/eval/upload…) backed by Firefox Agent Bridge; provider architecture for additional backends [VERIFIED-fetched:https://raw.githubusercontent.com/1jehuang/jcode/master/README.md]
- Embedding-triggered skill injection (skills not loaded at startup; conversation vector match auto-injects), cross-harness session resume (codex/claude/opencode/pi), agent-grep returning file-structure summaries with adaptive truncation, cache-cold warnings [VERIFIED-fetched:https://raw.githubusercontent.com/1jehuang/jcode/master/README.md]

## Notable absences
No permission/approval system documented anywhere in the README — swarm agents edit concurrently with no approval gate, and the safety docs exist but are not surfaced in the primary source. No memory scoping: nothing partitions memories by project/department/owner-sensitivity, no category ACL, no deny-by-default — the graph ingests everything the session touches. No audit log of swarm messages or consolidation decisions. Telemetry-free claims unexamined; sponsored-discovery docs hint at monetized content surfaces. The README's benchmark tables are self-reported without methodology links beyond jcode.sh/bench.
