# LongHorizon-Harness — Feature Dossier
Registry: #89 | Category: 01 | Verified: 1,197★, MIT, pushed 2026-08-20 (GitHub API 2026-08-24)

Skip-confirmation dossier. Recorded disposition: "Goal-state scheduled re-check adopted §14.6" (09-feature-extraction.md #89) — the spec already replaced daemon continuity with "the Automation-department scheduled re-check (§14.6) against stored goal state, never a resident worker" (§16.5 addendum). This dossier CONFIRMS that reading from the README — LongHorizon's loop is exactly goal-state-plus-re-entry — and details its computer-use loop mechanics against §16.7.

## Feature inventory
- **Loop engineering core**: give an agent a goal once; harness runs Plan → act → verify → checkpoint-or-recover → repeat "until the work is actually done"; each round rebuilds from original goal + verified state + failure evidence + remaining work; `max_rounds` default 30 bounds the loop [VERIFIED-fetched:https://raw.githubusercontent.com/AMAP-ML/LongHorizon-Harness/main/README.md]
- **Three-role split with independent audit**: Manager (state + next step), Executor ("starts with a fresh context and completes one clearly defined step"), Auditor ("independently inspects the actual files, interfaces, logs, and tests instead of trusting the Executor's claim"); "Only results that pass independent verification become trusted task state. A rejected result remains evidence, not progress" [VERIFIED-fetched:https://raw.githubusercontent.com/AMAP-ML/LongHorizon-Harness/main/README.md]
- **Goal-state durability across rounds**: on context refresh, action failure, or failed deliverable, the next round starts from original goal + last verified checkpoint; finished runs continue as conversations on the run's own round ledger; mid-round messages are claimed by the very next round so stopping never drops them [VERIFIED-fetched:https://raw.githubusercontent.com/AMAP-ML/LongHorizon-Harness/main/README.md]
- **Computer-use plugin tier**: pluggable GUI drivers (`codex-computer-use` official, `open-computer-use` npm, `clawdcursor`) wired as per-backend MCP configs under `~/.lh-harness/plugins/`, first-available-wins; install/consent separated from execution (`lh-harness plugin` only, `run` never mutates plugins); manual OS permission grants on macOS documented; GUI access scoped inside `~/.lh-harness/` so agent-native MCP registries stay untouched [VERIFIED-fetched:https://raw.githubusercontent.com/AMAP-ML/LongHorizon-Harness/main/README.md]
- **Mixed-surface tasks**: one task can move browser → CLI → desktop app → terminal validation while goal/progress/evidence stay under one state system; per-role episode timeouts (manager/auditor 600 s, executor 1800 s) keep partial trajectory and let the next round recover from the real workspace [VERIFIED-fetched:https://raw.githubusercontent.com/AMAP-ML/LongHorizon-Harness/main/README.md]
- **Run records**: every run stored in isolated `runs/<run-id>/` preserving task state, event stream, audit reports, role trajectories, workspace artifacts, final report — "inspectable, recoverable, reproducible"; final plain-language reply written "from the verified state alone"; `.lh-harness/` itself is off-limits to the running agents [VERIFIED-fetched:https://raw.githubusercontent.com/AMAP-ML/LongHorizon-Harness/main/README.md]
- **Local web workbench**: React/FastAPI dashboard at `127.0.0.1:8799`; start task, pick backend/model per role, answer approvals, instruct mid-run, stop/restart; bearer token REQUIRED for any non-loopback bind; human gates fire when blocked, needs-input, or failing repeatedly [VERIFIED-fetched:https://raw.githubusercontent.com/AMAP-ML/LongHorizon-Harness/main/README.md]
- **Backend wrapping**: AgentAdapters wrap existing vendor CLIs — Claude Code, Codex, OpenCode, DeepSeek Harness (`dsh --profile headless`) — preserving each one's native loop while the harness owns coordination; role-scoped read/write permissions per adapter (executors workspace-write, manager/auditors read-only); any-model-any-backend with per-role model assignment; measured gains reported on WeaveBench (+28.9 pass-rate), OSWorld 2.0 (3× binary), Terminal-Bench 2.1 (69.7→77.2%, 24% fewer tokens) vs bare Claude Code [VERIFIED-fetched:https://raw.githubusercontent.com/AMAP-ML/LongHorizon-Harness/main/README.md]

## Notable absences
No sandbox/isolation layer of its own — confinement delegates entirely to whatever the wrapped CLI provides (LastHarness must NOT make the same delegation; the Linux boundary stays). No egress control or domain allow-list anywhere. Audit reports gate progress but there is no immutable tamper-evident log — run dirs are ordinary files the harness could rewrite. No multi-owner/delegation model; the dashboard token is single-secret. macOS tested first, Windows untested-thorough — irrelevant to LastHarness's Linux boundary but confirms cross-platform enforcement drift seen elsewhere. Benchmark tables are self-reported.
