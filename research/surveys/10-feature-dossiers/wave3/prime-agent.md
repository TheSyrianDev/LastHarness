## Feature inventory
- **RLM core abstraction (known)**: "treats context as variables (*prompt-as-a-variable*) and tools like recursive subagents as function calls … inside a persistent REPL"; persistent IPython is the built-in model tool [VERIFIED-fetched:https://raw.githubusercontent.com/PrimeIntellect-ai/prime-agent/main/README.md]
- **Peer messaging (known conflict)**: "running agents can exchange messages and orchestrate one another without routing everything through the user"; retained subagents "discover one another" [VERIFIED-fetched:https://raw.githubusercontent.com/PrimeIntellect-ai/prime-agent/main/README.md]
- **Daemon-backed continuity (known conflict)**: "active sessions, IPython state, schedules, and subagents keep running when the terminal detaches and can be reattached later"; `prime-agent attach`, `status`, `doctor`, `shutdown` manage background services [VERIFIED-fetched:https://raw.githubusercontent.com/PrimeIntellect-ai/prime-agent/main/README.md]
- **NEW — Continual Harness**: `/refine` "reviews the current trajectory and can apply small, evidence-backed updates to supplemental harness state" (prompts, memories, skill descriptions, subagent specs); "It never rewrites the immutable base system prompt, and recorded snapshots support rollback" [VERIFIED-fetched:https://raw.githubusercontent.com/PrimeIntellect-ai/prime-agent/main/README.md]
- **NEW — Bounded autonomous mode**: `/autonomous` continues "within configured turn, token, and time budgets and can run user-defined quality gates. A passed gate checks only what that gate verifies; reaching a limit does not imply task success." [VERIFIED-fetched:https://raw.githubusercontent.com/PrimeIntellect-ai/prime-agent/main/README.md]
- **NEW — Persistent goals + heartbeats/schedules**: `/goal` keeps an objective active across turns until completed/paused/cleared; `/heartbeat`, `rlm_heartbeat`, `prime-agent schedule` re-enter sessions periodically or at set times; automatic compaction preserves long tasks [VERIFIED-fetched:https://raw.githubusercontent.com/PrimeIntellect-ai/prime-agent/main/README.md]
- **Explicit non-sandbox warning**: executes model-generated Python with user permissions; worker/kernel processes "are **not** a security sandbox" — external sandbox required for untrusted code [VERIFIED-fetched:https://raw.githubusercontent.com/PrimeIntellect-ai/prime-agent/main/README.md]
- Built on earendil-works/pi; JSON mode and RPC mode documented for headless automation; MIT [REPORTED-unverified:docs pages listed at https://github.com/PrimeIntellect-ai/prime-agent (README index) — page contents not fetched]

## Notable absences
No permission/approval gate anywhere — the README's own warning substitutes user vigilance for enforcement, reinforcing that LastHarness's deny-by-default gates must stay kernel-side. No memory taxonomy or scoping beyond free-form "memories" in supplemental state (no department/project partitioning). No egress controls; provider auth is subscription/API-key based. Rollback covers harness state but there is no immutable audit log of decisions.
