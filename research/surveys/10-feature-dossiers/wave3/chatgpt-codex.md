## Feature inventory
- **Codex CLI is open source (Apache-2.0) and runs locally**: "a coding agent from OpenAI that runs locally on your computer"; installed via curl script/npm/brew or release binaries; cloud counterpart ("Codex Web") is a separate hosted product at chatgpt.com/codex [VERIFIED-fetched:https://raw.githubusercontent.com/openai/codex/main/README.md]
- **Network OFF by default**: "By default, the agent runs with network access turned off"; in `workspace-write` mode "network access turned off unless you enable it in your configuration" via `[sandbox_workspace_write] network_access = true` [VERIFIED-fetched:https://learn.chatgpt.com/docs/agent-approvals-security.md]
- **OS-enforced sandboxing, platform-native**: macOS uses Seatbelt policies via `sandbox-exec -p`; Linux uses `bwrap` plus `seccomp`; Windows native sandbox or WSL2 (WSL1 dropped); spawned commands (`git`, package managers, test runners) inherit the same boundaries; `codex sandbox linux <cmd>` lets you test the boundary directly [VERIFIED-fetched:https://learn.chatgpt.com/docs/sandboxing.md and https://learn.chatgpt.com/docs/agent-approvals-security.md]
- **Two-layer control model**: sandbox mode (read-only / workspace-write / danger-full-access) defines technical boundaries; approval policy (untrusted / on-request / never) decides when the agent must stop; Auto preset = workspace-write + on-request; read-only recommended for non-version-controlled folders [VERIFIED-fetched:https://learn.chatgpt.com/docs/agent-approvals-security.md]
- **Protected paths inside writable roots**: `<root>/.git` (including gitdir pointer resolution), `.agents`, `.codex` are recursively read-only even in workspace-write mode [VERIFIED-fetched:https://learn.chatgpt.com/docs/agent-approvals-security.md]
- **`network_proxy` feature — allowlist-first egress for enabled networks**: destination rules apply to scripts/programs/subprocesses; domain rules are allowlist-first with exact/scoped-wildcard/apex-inclusive matching, "`deny` always wins over `allow`"; `allow_local_binding = false` blocks loopback/link-local/private destinations by default; best-effort DNS-rebinding checks block lookups resolving to non-public addresses; SOCKS5 support; Unix-socket destinations allowlist-only; proxy listeners loopback-only; explicit table of dangerous overrides [VERIFIED-fetched:https://learn.chatgpt.com/docs/agent-approvals-security.md]
- **Scope honesty about what the proxy does NOT cover**: it filters command-sandbox traffic only — web search, connector/MCP tool calls, browser/computer-use, cloud tasks, and model/auth traffic use separate controls; web search defaults to a cached index rather than live fetches to reduce prompt-injection exposure [VERIFIED-fetched:https://learn.chatgpt.com/docs/agent-approvals-security.md]
- **Cloud two-phase runtime (the ❌ half, documented)**: Codex cloud runs in isolated OpenAI-managed containers; setup phase has network for dependency install, agent phase runs offline by default unless internet access is enabled per environment; secrets configured for cloud environments exist only during setup and are removed before the agent phase starts [VERIFIED-fetched:https://learn.chatgpt.com/docs/agent-approvals-security.md]
- **Automatic approval review (guardian)**: `approvals_reviewer = "auto_review"` routes eligible approvals (sandbox escalations, blocked network requests, side-effecting tool calls) through a reviewer agent that checks exfiltration/credential-probing/security-weakening/destructive actions; policy "denies critical-risk", high-risk needs user authorization + no deny rule; "Prompt-build, review-session, and parse failures fail closed"; default reviewer policy ships IN the OSS repo at codex-rs/core/src/guardian/policy.md [VERIFIED-fetched:https://learn.chatgpt.com/docs/agent-approvals-security.md]
- **Telemetry opt-in only**: OTel export off by default ("keep local runs self-contained"), prompt text redacted unless explicitly enabled, guidance to route only to collectors you control [VERIFIED-fetched:https://learn.chatgpt.com/docs/agent-approvals-security.md]
- **Secure devcontainer reference**: `.devcontainer/devcontainer.secure.json` + Ubuntu image + `init-firewall.sh` applying allowlist-driven outbound firewall + bubblewrap kept usable inside the container; docs warn DNS-rebinding protections belong at the firewall layer too [VERIFIED-fetched:https://learn.chatgpt.com/docs/agent-approvals-security.md]

## Notable absences
The repo itself now carries almost no operational documentation — sandbox.md and config.md are stubs pointing at learn.chatgpt.com/developers.openai.com, so "from the OSS repo" mechanically means the Apache-2.0 code plus the guardian policy file; everything behavioral above is doc-claimed official material, not independently reproducible from the README alone. No self-hosted control plane exists for the cloud half. The network proxy's honest scope statement (MCP/browser/model traffic bypass it) is itself the caution: LastHarness must route ALL worker egress through its gateway, not only shell-command traffic. License clean (Apache-2.0); nothing here disturbs the recorded split — local sandbox mechanics → §7.1 note, cloud half → skip.
