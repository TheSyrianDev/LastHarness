## Feature inventory
- Two-axis skill organization: discipline folders (`skills/engineering/`, `skills/productivity/`) crossed with an invocation class — **user-invoked** (orchestrators, reachable only when typed) vs **model-invoked** (reusable disciplines the agent may auto-reach); rule: a user-invoked skill may invoke model-invoked skills but never another user-invoked one [VERIFIED-fetched:https://raw.githubusercontent.com/mattpocock/skills/main/README.md]
- Frontmatter conventions verified on-disk: `name`, `description`, and `disable-model-invocation: true` marking user-invocation enforcement; wrapper bodies can be a single line delegating to a shared primitive (`grill-me` → "Call the Skill tool with 'grilling'") [VERIFIED-fetched:https://raw.githubusercontent.com/mattpocock/skills/main/skills/productivity/grill-me/SKILL.md]
- Grill-me scoping pattern: `/grill-me` (relentless interview until every branch of the design tree resolves) and `/grill-with-docs` (same, plus building the project's domain model — sharpening terminology, updating `CONTEXT.md` and ADRs inline); backed by the reusable model-invoked `grilling` interview primitive also used by `triage`, `wayfinder`, and `improve-codebase-architecture` [VERIFIED-fetched:https://raw.githubusercontent.com/mattpocock/skills/main/README.md]
- Shared-language discipline: ubiquitous-language `CONTEXT.md` so agents decode project jargon ("materialization cascade" vs 20 words of explanation), cutting tokens and misalignment; supported by `domain-modeling`, `wait-what` (re-pitches messages in plain English using CONTEXT.md vocabulary), and `writing-for-agents` (docs authored for agent consumption) [VERIFIED-fetched:https://raw.githubusercontent.com/mattpocock/skills/main/README.md]
- Engineering workflow loop: `/setup-matt-pocock-skills` once-per-repo config (issue tracker choice: GitHub/Linear/local files; triage labels; docs location), `/triage` state machine of triage roles, `/to-spec`, `/to-tickets` tracer-bullet tickets declaring blocking edges, `/implement` driving `/tdd` at pre-agreed seams then `/code-review`, `/wayfinder` planning oversized work as decision-ticket maps, `/improve-codebase-architecture` deepening survey, two-axis `/code-review` (Standards + Spec) as parallel isolated sub-agents, `/diagnosing-bugs` red-first loop, `/research` cited-Markdown capture against primary sources, `/wizard` interactive bash generator for steps only a human can perform [VERIFIED-fetched:https://raw.githubusercontent.com/mattpocock/skills/main/README.md]
- Distribution duality: Claude Code official-marketplace plugin (managed, read-only, auto-updating bundle) vs `npx skills@latest add mattpocock/skills` (editable copies owned by the project); positioning statement: process frameworks like GSD/BMAD/Spec-Kit "take away your control" while these stay small and composable [VERIFIED-fetched:https://raw.githubusercontent.com/mattpocock/skills/main/README.md]

## Notable absences
No sandboxing, permission, or tool-policy mechanics — trusts the host harness entirely; execution locality is undefined (any-model claim means any *provider* too). No memory system beyond CONTEXT.md/ADRs (no cross-session store). No evaluation harness for the skills themselves. Single-author doctrine: opinions are coherent but uncontestable in-repo. The grilling pattern overlaps LastHarness's existing grilling skill — adopt refinements, not the base.
