Skip-confirmation dossier. Recorded disposition: overkill vs SQLite FTS5 + in-process vectors at single-owner scale. This dossier CONFIRMS from primary docs on footprint, JVM, and licensing.

## Feature inventory
- **Positioning is production-scale by design**: "distributed search and analytics engine, scalable data store and vector database optimized for speed and relevance on production-scale workloads"; use cases span RAG, vector search, full-text, logs, metrics, APM, security logs [VERIFIED-fetched:https://raw.githubusercontent.com/elastic/elasticsearch/main/README.asciidoc]
- **Recommended local path is Docker ×2 containers**: the README's "Run Elasticsearch locally" spins up Elasticsearch AND Kibana via the `start-local` script (`curl -fsSL https://elastic.co/start-local | sh`), ports 9200/5601, with an explicit "[WARNING] DO NOT USE THESE INSTRUCTIONS FOR PRODUCTION DEPLOYMENTS" and a one-month trial license reverting to Free Basic [VERIFIED-fetched:https://raw.githubusercontent.com/elastic/elasticsearch/main/README.asciidoc]
- **Cluster machinery is the default mental model**: nodes join by shared `cluster.name`; loopback binding = development mode (bootstrap failures warn) while any non-loopback `network.host` flips checks to startup exceptions; discovery needs `discovery.seed_hosts` and first-form clusters need `cluster.initial_master_nodes`, with quorum warnings that auto-bootstrapping is "inherently unsafe" [VERIFIED-fetched:https://www.elastic.co/guide/en/elasticsearch/reference/current/heap-size.html]
- **JVM footprint surface**: heap auto-sized from node roles + total memory; JVM heap-dump path and fatal-error-log settings to configure; GC logging enabled by default rotating at 64 MB and able to consume "up to 2 GB of disk space"; `jvm.options.d` override directory; DNS-cache/security-manager tuning knobs [VERIFIED-fetched:https://www.elastic.co/guide/en/elasticsearch/reference/current/heap-size.html]
- **Backup rule is snapshot-only**: "Taking a snapshot is the only reliable and supported way to back up a cluster… There are no supported methods to restore any data from a file system-level backup" — filesystem copies may corrupt or silently lose data; data directories must not be virus-scanned or manually touched [VERIFIED-fetched:https://www.elastic.co/guide/en/elasticsearch/reference/current/heap-size.html]
- **Licensing stack**: LICENSE.txt default is triple-license AGPLv3-only / SSPL v1 / ELv2; code solely under ELv2 lives in `x-pack/`; GitHub API therefore reports NOASSERTION; subscription tiers are "Free and open - Basic", Platinum (existing customers only), Enterprise, with Gold discontinued — advanced security (SSO/SAML/OIDC/Kerberos/JWT, field- and document-level security, audit logging, encryption-at-rest support, FIPS mode) and ML/AI features are distributed across paid tiers in the subscription matrix [VERIFIED-fetched:https://www.elastic.co/subscriptions]
- **Feature breadth far past single-owner search**: ES|QL (+lookup joins, subqueries, cross-cluster), retrievers incl. RRF hybrid, Learning to Rank, GPU vector indexing, aggregations family, ML nodes with ELSER/e5/Elastic Rerank packaged models, Agent Builder with MCP/A2A integrations, Fleet/Elastic Agent ingest fleet, Kibana dashboards/alerting/case management [VERIFIED-fetched:https://www.elastic.co/subscriptions]

## Notable absences
No embedded or in-process mode exists — the smallest honest deployment is a service (and realistically a pair with Kibana). No story sized below "cluster": even dev mode speaks nodes/bootstrap/quorums. Local persistence rules actively forbid the file-level backup habit LastHarness relies on for SQLite. Security posture depends partly on paid tiers for exactly the gating primitives LastHarness treats as baseline. Nothing about department-scoped memory or decision-log integration — it is infrastructure, not an agent component.
