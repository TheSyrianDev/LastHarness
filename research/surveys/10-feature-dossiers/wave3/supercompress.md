# SuperCompress (Supercompress/Supercompress) — Feature Dossier
Registry: #13 | Category: 02 | Verified: 61 stars, MIT, last push 2026-08-22 (GitHub API 2026-08-24)

Skip-confirmation dossier. Recorded disposition: query-aware retrieval ≈ §6.3 bounded access. This dossier CONFIRMS that skip and finds a second, stronger reason: the compression execution is hosted third-party cloud with billing.

## Feature inventory
- **Query-aware compression mechanism**: takes long context + current query → segments and scores blocks by relevance to THAT query → keeps answer-critical lines "in their original wording", keeps entities/errors/definitions/nearby dependencies, drops the rest; ~65% fewer input tokens claimed; "The **query is never compressed** — only the surrounding context" [VERIFIED-fetched:https://raw.githubusercontent.com/Supercompress/Supercompress/main/README.md]
- **Anti-truncation/anti-summarization positioning**: truncate deletes the middle where answers live; summarize rewrites evidence so "IDs, stack traces, and exact errors get soft"; SuperCompress claims verbatim-evidence retention with auditable kept lines [VERIFIED-fetched:https://raw.githubusercontent.com/Supercompress/Supercompress/main/README.md]
- **Benchmark table (self-published)**: at fixed 35% keep-budget, answer-critical lines kept — FIFO/truncation 24.8%, summarization 60.5%, H2O 97.9%, SuperCompress 100%; plus compiler-mode ~62% avg savings, 100% answer retention on LongBench + hard haystacks (66/66), token-weighted ~74% cut; methodology hosted at supercompress.dev/benchmarks [VERIFIED-fetched:https://raw.githubusercontent.com/Supercompress/Supercompress/main/README.md]
- **Two products, one engine — and the engine side is HOSTED**: coding-agent plugin (`npm i -g supercompress-proxy && npx supercompress setup`, MCP `compress_context` on big dumps, account linking via dashboard) and API/Python path where `api/` is documented in the repo map as "**Hosted API + billing**" [VERIFIED-fetched:https://raw.githubusercontent.com/Supercompress/Supercompress/main/README.md]
- **Cloud round-trip is the primary path**: Python client needs `SUPERCOMPRESS_API_KEY=sc_live_…`; REST example POSTs context to `https://www.supercompress.dev/api/v1/compress` with `X-API-Key` header — i.e., your RAG chunks/logs/tool dumps are sent to a third-party service to be compressed [VERIFIED-fetched:https://raw.githubusercontent.com/Supercompress/Supercompress/main/README.md]
- **Repo layout admits an OSS/private split**: `packages/proxy` (npm plugin), `api/` (hosted API + billing), `web/`, `supercompress/` (Python package); "Private marketing, outreach, and model training stay out of this repo" per `docs/REPO_LAYOUT.md` — the scoring core's server side is not shown as self-hostable [VERIFIED-fetched:https://raw.githubusercontent.com/Supercompress/Supercompress/main/README.md]

## Per-feature verdict
| Feature | Type | LastHarness landing | Rationale |
|---|---|---|---|
| Query-aware block scoring keeping verbatim evidence | 🧩 Mechanism only | Validates existing §6.3 bounded access | The recorded skip confirmed: LastHarness's bounded-access model already scores and gates what a worker may retrieve per task/query. SuperCompress is the same principle applied at prompt-assembly time, not a new capability. |
| Verbatim-evidence preservation vs summarization ("keep the evidence, drop the filler") | 🧩 Mechanism only | §6.3 design-note reinforcement | Independently validates LastHarness's choice to harvest exact artifacts into the immutable log rather than lossy summaries; the oracle-recall-vs-truncation table is citable ammunition for that policy. |
| Hosted compress API + billing + `sc_live_` keys (`api/v1/compress`) | ❌ Conflict-skip | — | STRONGER skip reason found: WHERE DOES EXECUTION HAPPEN? On supercompress.dev's cloud. Agent contexts (code, logs, secrets-adjacent dumps) would egress to a third party — violates local-first inference, default-deny egress gateway, and the ONE Linux-env boundary. |
| Account-linked agent setup (`npx supercompress setup` links dashboard account) | ❌ Conflict-skip | — | Same boundary conflict at install time; ties local agent config to a hosted identity/billing account. |
| MCP `compress_context` plugin shape | 🧩 Mechanism only | Kernel tool-surface note | Exposing compression as one allow-listable tool on large dumps is a tidy interface shape; the kernel could offer equivalent locally if ever needed. |

## Notable absences
No self-hosted/server-side-open path: the repo shows the npm plugin and a thin Python client, while scoring/billing/api internals live behind the hosted service — the MIT license covers less than the product. No offline or local-inference mode documented anywhere in the README. No third-party benchmark replication; all numbers self-published on their own site. Very small project surface (61 stars, 19 forks, created 2026-07-31) with bus-factor-1 signals. Nothing on memory, persistence, egress controls, or audit logging — it is a single-purpose compression endpoint.
