Skip-confirmation dossier. Recorded disposition: "Worktree fan-out + bounded concurrency already spec'd" (09-feature-extraction.md #79) — LastHarness §16.1 already specifies `git worktree add` as zero-copy working-directory staging for concurrent dispatches ("a correctness and concurrency tool, not a containment tool"), and §7.1 caps `max_concurrent_agents: 5`. NOT Apache Superset (the BI engine) — disambiguation already recorded in 01-coding-agents.md and 99-corrections.md. This dossier CONFIRMS the skip from the README: Superset is an Electron IDE orchestrating 100+ vendor CLI agents, each in its own worktree.

## Feature inventory
- **Parallel workspaces over git worktrees**: "Run 100+ coding agents at once, each in its own git worktree with its own branch, terminal, and environment. Compare the results and merge the winner"; works with any terminal CLI agent (Claude Code, Codex, Cursor Agent, Gemini CLI, Grok, Pi, OpenCode, etc.) using the user's own subscriptions; "If it runs in a terminal, it runs on Superset" [VERIFIED-fetched:https://raw.githubusercontent.com/superset-sh/superset/main/README.md]
- **Agent monitoring**: sidebar status per agent with working indicators, completion chimes, dock badges when an agent needs attention [VERIFIED-fetched:https://raw.githubusercontent.com/superset-sh/superset/main/README.md]
- **Built-in terminal + diff viewer + in-app browser**: tabbed/split persistent terminals surviving restarts; rich prompt editor with @-file mentions (⌘I); inspect/comment/edit agent changes without leaving the app, then commit/push; dev-server preview pane with per-workspace port detection [VERIFIED-fetched:https://raw.githubusercontent.com/superset-sh/superset/main/README.md]
- **Automations**: agent sessions on a schedule — "triage issues overnight, draft the weekly changelog, keep dependencies fresh" [VERIFIED-fetched:https://raw.githubusercontent.com/superset-sh/superset/main/README.md]
- **Remote workspaces**: connect another machine and reach its workspaces from desktop app, CLI, or phone; wake offline hosts with a custom command; hosts/members managed in organization settings [VERIFIED-fetched:https://raw.githubusercontent.com/superset-sh/superset/main/README.md]
- **CLI / SDK / MCP surfaces**: single `superset` binary to create workspaces, launch agents, read their terminals, manage automations; TypeScript SDK (`@superset_sh/sdk`); MCP server so Claude Code/Codex/Cursor "create and manage workspaces themselves" [VERIFIED-fetched:https://raw.githubusercontent.com/superset-sh/superset/main/README.md]
- **Built-in orchestration skills**: agents pre-loaded with `superset:*` skills (orchestrate parallel agents, schedule automations, file feedback, diagnose issues), provisioned automatically at launch [VERIFIED-fetched:https://raw.githubusercontent.com/superset-sh/superset/main/README.md]
- Integrations: Slack & Linear workspace spin-up, IDE handoff, custom themes, remappable shortcuts, bring-your-own providers (OpenRouter/Bedrock/Vertex/Vercel AI Gateway); Electron+React+Bun stack; macOS primary target, Linux AppImage experimental, Windows absent; desktop app free forever under ELv2 (no repackaging-as-a-service); dev setup uses local Postgres via Docker [VERIFIED-fetched:https://raw.githubusercontent.com/superset-sh/superset/main/README.md]

## Per-feature verdict
| Feature | Type | LastHarness landing | Rationale |
|---|---|---|---|
| Worktree-per-task fan-out of concurrent agents | 🧩 Mechanism only (already spec'd) | Confirms §16.1 worktree staging | Confirms the recorded skip exactly: LastHarness's dispatch contract input 2 already hands every worker a fresh git worktree (§16.6). Superset validates the pattern works at scale — but its 100+ count reflects UI convenience, not a policy decision; LastHarness keeps the §7.1 `max_concurrent_agents: 5` ceiling |
| Orchestrating wrapped vendor CLI agents via subscription auth | ❌ Conflict-skip (confirmed) | §16.2 SDK lock | The orchestrated substrate is precisely what LastHarness excluded — external CLIs with subscription auth are the second-substrate failure mode; no amount of orchestration polish changes WHERE execution happens (locally) but it changes WHOSE harness runs it |
| Sidebar monitoring, completion chimes, needs-attention badges | 🧩 Mechanism only | Owner-console status surface §13.4 / R7 | The observe-and-be-notified UX for many concurrent dispatches maps onto LastHarness's owner console watching kernel-routed workers; notifications ride the owner notification queue (§14.6 alert_dispatcher), never direct worker-to-owner channels |
| Diff viewer + review-before-merge workflow | 🧩 Mechanism only | Manager-reads-git principle §16.6 output 2 | Independent confirmation that the artifact diff is the review surface of record — "compare the results and merge the winner" is the manual version of LastHarness's verify-before-promote (§11.3) |
| Scheduled automations (overnight triage, changelog, dependency refresh) | 🧩 Mechanism only | Automation dept scheduled jobs §14.6 | Same shape as the Automation department's cron-driven re-checks against stored goal state; confirms demand for scheduled non-interactive dispatch, which LastHarness implements as kernel-routed scheduled jobs, not resident processes |
| Remote workspaces across multiple machines w/ wake-on-demand | ❌ Conflict-skip | §16.1 one-boundary rule | LastHarness has exactly ONE Linux-environment boundary on the owner's machine; federating execution across a fleet of member hosts (with org settings) exceeds the single self-hosted boundary even though hosts are self-owned — multi-host is an unscoped architecture change requiring explicit correction |
| MCP server letting agents create/manage workspaces themselves | ❌ Conflict-skip | §16.5 kernel-only dispatch authority | Workers self-provisioning new workspaces/agents bypasses the manager-dispatch model; only the kernel's Department Creation component spawns execution contexts (§14.1) |
| `superset:*` auto-provisioned orchestration skills | 🧩 Mechanism only | Skill-pack precedent §5.3 acquisition | Auto-provisioning role-scoped skills at launch parallels department.config skill lists; the specific skills orchestrate a foreign substrate and don't transfer |

## Notable absences
No bounded-concurrency control documented — the pitch is "100+" with no queue, budget, or resource ceiling visible in the README (LastHarness's §7.1 limits have no equivalent here). No security model for the remote-workspace tier beyond org membership (no token/session lifecycle like T3's pairing, no transport hardening guidance). No audit log — monitoring state is ephemeral UI, nothing indicates persistence of who-did-what across restarts beyond the repos' own git history. No approval gate on agent actions (relies on each CLI's native permissions). Elastic License 2.0 is source-available, not OSI open source.
