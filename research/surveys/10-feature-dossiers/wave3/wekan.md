# Wekan — Feature Dossier
Registry: #15 | Category: 08 | Verified: 21,059 stars, MIT, pushed 2026-08-24 (GitHub API 2026-08-24)

Skip-confirmation dossier. Recorded disposition: kanban board skipped as a product; the surviving idea is the read-only board render of routing-queue/notification states as an R7 owner-console pattern. This dossier CONFIRMS the skip from the primary source, sizes the actual runtime footprint, and states what a read-only embed would need.

## Feature inventory
- **Self-hosted open-source collaborative kanban**: "completely Open Source and Free software collaborative kanban board application with MIT license"; users are encouraged to self-install ("you don't have to trust us with your data"); real-time user interface; largest known deployment ~30k company users [VERIFIED-fetched:https://raw.githubusercontent.com/wekan/wekan/master/README.md]
- **Runtime footprint (the decisive fact)**: main branch runs Meteor 3.5 on Node.js 24.x with a MongoDB backend; README warns "If you run out of disk space, MongoDB database gets corrupted", requires minimum 1 GB RAM free (4 GB total production), daily mandatory backups, and frequent security updates because old bundled Node.js versions accumulate CVEs; scale-out recipe is 3 frontend servers × 2 containers plus a dedicated DB server [VERIFIED-fetched:https://raw.githubusercontent.com/wekan/wekan/master/README.md]
- **Distribution matrix**: Docker images on GHCR/Quay/Docker Hub with docker-compose.yml, Snap, Sandstorm, and "one-click installation on various platforms" [VERIFIED-fetched:https://raw.githubusercontent.com/wekan/wekan/master/README.md]
- **Roadmap served as a public READ-ONLY board**: WeKan's own roadmap/demo is a public read-only board at boards.wekan.team — the vendor itself uses the board as a publish/visibility surface, not just an editing tool [VERIFIED-fetched:https://raw.githubusercontent.com/wekan/wekan/master/README.md]
- **Internationalization at scale**: 234 languages translated (142 essentially complete) via Transifex; Standard for Public Code assessment meets 8/16 criteria [VERIFIED-fetched:https://raw.githubusercontent.com/wekan/wekan/master/README.md]
- **No API/webhook surface in the primary source**: the README documents no REST API, webhook, or programmatic-integration story at all — development docs, FAQ, wiki Features page, and issue tracker are the only extension points named [VERIFIED-fetched:https://raw.githubusercontent.com/wekan/wekan/master/README.md]

## Notable absences
No API, webhook, plugin, or agent-facing surface appears anywhere in the README — there is nothing here for an agent to integrate with even if the stack were acceptable. No authentication/authorization model is described at the primary-source level. The README's own operational warnings (MongoDB corruption on disk-full, no undo, manual database repair when boards won't load) argue against adopting it as durable state infrastructure. Nothing touches egress, memory gating, or decision logging. Extraction stops at the read-only-render idea; the footprint confirmation (Meteor + Node 24 + MongoDB, multi-server scale-out) closes the door on any embed-by-running variant.
