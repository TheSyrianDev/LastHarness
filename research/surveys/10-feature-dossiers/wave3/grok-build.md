# Grok Build — Feature Dossier
Registry: #49 | Category: 01 | Verified: 25,979★, Apache-2.0, pushed 2026-08-23 (GitHub API 2026-08-24)

Note-tier confirmation dossier. Recorded disposition: "Agent-client protocol split for future owner surfaces" (09-feature-extraction.md #49) — the harness itself is a wrapped vendor CLI excluded under the §16 header / §16.2 SDK lock ("no wrapped external CLI"). This dossier CONFIRMS that disposition from the README and inventories the harness's DISTINCT mechanics: fullscreen pager TUI, Agent Client Protocol embedding, OS-kernel sandboxing, and a layered permission pipeline.

## Feature inventory
- **Fullscreen interactive TUI ("pager")**: terminal-based AI coding agent that "understands your codebase, edits files, executes shell commands, searches the web, and manages long-running tasks"; runs as a full-screen mouse-interactive TUI (separate `xai-grok-pager` render crate over an `xai-grok-shell` agent runtime); interactive, headless (`grok -p`), or embedded-in-editor via ACP; repo is periodically synced from the vendor monorepo, external contributions not accepted [VERIFIED-fetched:https://raw.githubusercontent.com/xai-org/grok-build/main/README.md]
- **Agent Client Protocol (ACP) split**: agent runtime exposed as `grok agent stdio` and `grok agent serve --bind 127.0.0.1:2419 --secret <token>`; editor/UI clients drive sessions over the protocol; ACP clients can set `_meta.yoloMode` on `session/new`; headless/stdio/serve sessions always start in `ask` mode unless overridden [VERIFIED-fetched:https://raw.githubusercontent.com/xai-org/grok-build/main/crates/codegen/xai-grok-pager/docs/user-guide/22-permissions-and-safety.md]
- **OS-kernel sandbox (not per-command wrapping)**: Landlock on Linux (kernel ≥5.13), Seatbelt on macOS; applied to the ENTIRE grok process at startup so bash/grep/subagents inherit restrictions; built-in profiles `workspace`/`devbox`/`read-only`/`strict`; custom `sandbox.toml` profiles add `read_only`/`read_write`/glob `deny` lists enforced via bwrap bind-over (Linux) or Seatbelt regex (macOS); fail-closed — malformed profiles or missing bubblewrap refuse startup rather than under-enforce; child-process network blocked via seccomp on Linux only (no-op on macOS); sandbox is irreversible once applied and the profile is saved with, and restored with, the session — resuming with a different profile is refused [VERIFIED-fetched:https://raw.githubusercontent.com/xai-org/grok-build/main/crates/codegen/xai-grok-pager/docs/user-guide/18-sandbox.md]
- **Sandbox hardening against hook hijack**: under restrictive profiles the kernel write-denies Grok's own global hook sources (`~/.grok/hooks/`, `hooks-paths`) while keeping them readable; symlinked `$GROK_HOME` or symlinked hook targets refuse to start; parent dirs pinned against rename [VERIFIED-fetched:https://raw.githubusercontent.com/xai-org/grok-build/main/crates/codegen/xai-grok-pager/docs/user-guide/18-sandbox.md]
- **Layered permission pipeline**: ordered checks — PreToolUse hooks → merged allow/ask/deny rules (`deny` > `ask` > `allow`, across all scopes; a global deny cannot be overridden by a project allow) → remembered per-command grants (per-project scope, dangerous-command list always re-prompts) → built-in read-only auto-approvals → mode policy (`default`/`acceptEdits`/`auto`/`dontAsk`/`bypassPermissions`); chained commands split on `&&`/`||`/`;`/pipes — deny/ask checked per segment, allow requires EVERY segment to match; admin lock file (`requirements.toml`) can disable always-approve org-wide; reads Claude-compatible `.claude/settings.json` natively [VERIFIED-fetched:https://raw.githubusercontent.com/xai-org/grok-build/main/crates/codegen/xai-grok-pager/docs/user-guide/22-permissions-and-safety.md]
- **Documented hooks fail-open**: "If a hook script crashes, times out, or is missing, the tool call proceeds as if the hook had allowed it" — hooks explicitly NOT a security boundary unless self-hardened [VERIFIED-fetched:https://raw.githubusercontent.com/xai-org/grok-build/main/crates/codegen/xai-grok-pager/docs/user-guide/22-permissions-and-safety.md]
- **Shell environment secret scrubbing**: `[shell_environment_policy]` filters inherited env vars for tool subprocesses — `inherit` all/core/none, default drop of `*KEY*`/`*SECRET*`/`*TOKEN*` patterns, exclude/include_only lists, forced `set` values [VERIFIED-fetched:https://raw.githubusercontent.com/xai-org/grok-build/main/crates/codegen/xai-grok-pager/docs/user-guide/18-sandbox.md]
- Ecosystem surface: MCP servers, skills, plugins, hooks, plan mode, subagents, background tasks, checkpoints, dashboard, usage monitoring documented as user-guide chapters; first-party code Apache-2.0 with in-tree source ports of openai/codex and sst/opencode tool implementations [REPORTED-unverified:user-guide index at https://github.com/xai-org/grok-build/tree/main/crates/codegen/xai-grok-pager/docs/user-guide — chapter contents not individually fetched]

## Notable absences
No immutable audit log — permission decisions appear in the transcript but nothing indicates an append-only record; sandbox events go to a local debug JSONL, not a decision ledger. Sandbox is opt-in and OFF by default (the safe profile must be chosen, inverting LastHarness's deny-by-default stance). Child-network blocking silently degrades to a no-op on macOS (platform asymmetry LastHarness avoids by having exactly one Linux boundary). No egress domain allow-list below the coarse network-block flag (web tools are always exempt from network restriction). No multi-owner or delegation model — admin locks exist but grants are personal per-machine state.
