# img2threejs — Feature Dossier
Registry: #131 | Category: 07 | Verified: 13,266 stars, Apache-2.0, pushed 2026-08-24 (GitHub API 2026-08-24; matches registry ~13.2k★ / pushed 2026-08-24)

NEW registration (cat 07). Note-tier dossier. Recorded disposition: photo → **code-only** procedural Three.js reconstruction, quality-gated and animation-ready → §16.4 adjacent capability. Litmus first: execution stays in-boundary — reconstruction runs inside a coding agent (local-first LLM) plus deterministic Python 3.10+ stdlib scripts; rendering authority is a browser Three.js route; no cloud service anywhere in the core pipeline. The code-only pipeline in detail: one reference image → `ObjectSculptSpec` JSON (component tree, materials, repetition systems, sockets, recorded review history) → TypeScript `createObjectNameModel(spec, options)` factory returning a `THREE.Group` with `root.userData.sculptRuntime` (nodes, sockets, colliders) — diffable text artifacts, never mesh binaries.

## Feature inventory
- Code-only contract: image → spec JSON + TS `THREE.Group` factory built from primitives/procedural shaders/generated geometry; explicitly *not* photogrammetry, mesh extraction, or downloaded packs; outputs are "diffable TypeScript plus a JSON spec… instead of multi-megabyte mesh files" [VERIFIED-fetched:https://raw.githubusercontent.com/img2threejs/img2threejs/main/README.md]
- Staged pass pipeline with vision-review loop: `blockout → structural → form → material → surface → lighting → interaction → optimization`, generated and reviewed one pass at a time, self-correcting until every identity-defining feature clears its threshold [VERIFIED-fetched:https://raw.githubusercontent.com/img2threejs/img2threejs/main/README.md]
- Quality gate — fail-closed before codegen: `--strict-quality` validation blocks shallow specs so no tokens are spent rendering an underspecified model; on failure the generator returns `BLOCKED` with spec artifact, failure metrics, causes, next action, and writes no factory (`--allow-nonstrict` is legacy-test-only) [VERIFIED-fetched:https://raw.githubusercontent.com/img2threejs/img2threejs/main/README.md]
- Quality gate — detail inventory: pipeline enumerates a `detailInventory` of identity-defining details (gloss, bevels, screws/rivets, linework, wear); every detail must map to a real component/material entry or be dropped, never faked; strict gate blocks generation until complete [VERIFIED-fetched:https://raw.githubusercontent.com/img2threejs/img2threejs/main/README.md]
- Quality gate — per-pass evidence review: each pass judged from exactly one packaged reference-vs-render comparison sheet; per-region confidence reported for anything the image cannot show; unseen faces inferred by mirroring and marked low-confidence; "this cannot reach the requested fidelity from this image" is a valid, expected result [VERIFIED-fetched:https://raw.githubusercontent.com/img2threejs/img2threejs/main/README.md]
- Domain-specific gates: CS2 weapon review contracts (exactness tier, family identity, component coverage, map-stripped blockout so textures can't stand in for structure); material acceptance gate (registry/crop/render/comparison evidence); hard scalp-exposure gate + soft hair gate for characters; chirality gates; interior-difference review required per visual pass [VERIFIED-fetched:https://raw.githubusercontent.com/img2threejs/img2threejs/main/README.md]
- Scripts-enforce/model-judges split: ~90 deterministic Python stdlib-only forge modules handle validation, gating, PBR extraction, comparison-sheet packaging, state; scripts never score visuals — model tokens go only to visual judgment and code [VERIFIED-fetched:https://raw.githubusercontent.com/img2threejs/img2threejs/main/README.md]
- Animation-ready output contract: runtime hierarchy with pivots/sockets/colliders and `userData.tick`; character builds add `root.userData.rig` (bones, shared Skeleton, bound flag) derived via skeleton-from-component-tree + geodesic skinning with a blocking payload-integrity gate before any `THREE.Skeleton` binds [VERIFIED-fetched:https://raw.githubusercontent.com/img2threejs/img2threejs/main/README.md]
- Subject routing fail-closed: object/character/hybrid classification routes pipelines (hard-surface vs anatomy-aware character track vs creature body plans); low-confidence routing resolves to `request-input`, never a guess [VERIFIED-fetched:https://raw.githubusercontent.com/img2threejs/img2threejs/main/README.md]
- Resumable workflow: `forge/state.py init` writes an ordered evidence-backed checklist; `forge/next.py --state` resumes mid-reconstruction while existing spec/render/review gates stay authoritative [VERIFIED-fetched:https://raw.githubusercontent.com/img2threejs/img2threejs/main/README.md]
- Optional evidence layer that can never approve passes: SAM2 masks, Depth Anything V2 depth priors, MediaPipe landmarks, Playwright fallback, Context7 retrieval — isolated tooling providing measurements only [VERIFIED-fetched:https://raw.githubusercontent.com/img2threejs/img2threejs/main/README.md]
- Agent-host packaging: installs as a skill into Claude Code/Codex/OpenCode (`~/.claude/skills/img2threejs` symlink pattern), agent-agnostic over whatever vision/browser tools the host provides [VERIFIED-fetched:https://raw.githubusercontent.com/img2threejs/img2threejs/main/README.md]

## Notable absences
No server/API surface at all — it is a skill, not a service, so scaling means repeated agent dispatches rather than a queue (fine for ephemeral workers, untested at batch scale). Single-image limits are honestly documented (hidden sides mirrored, stylized-not-photoreal characters) but there is no automated multi-view capture story beyond opt-in silhouette carving. Demo registry itself flags some showcases as `placeholder` status — quality variance is real. No license concerns (Apache-2.0), but provenance of trained judgment lives entirely in prompt/rubric docs (`grimoire/`) — version-pinning those files matters as much as pinning code.
