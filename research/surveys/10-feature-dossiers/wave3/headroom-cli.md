# Headroom CLI (headroomlabs-ai/headroom) — Feature Dossier
Registry: #12 | Category: 02 | Verified: 67,355 stars, Apache-2.0, last push 2026-08-24 (GitHub API 2026-08-24)

Note-tier dossier. Recorded disposition: reversible compression + restore-on-demand → §7.1 design-note. Restore mechanics detailed below per tasking.

## Feature inventory
- **Four integration shapes over one pipeline**: inline library (`compress(messages)` Python/TS), local proxy (`headroom proxy --port 8787`, zero code changes), agent wrapper (`headroom wrap claude|codex|...` with `unwrap` undo), MCP server (`headroom_compress`, `headroom_retrieve`, `headroom_stats`) [VERIFIED-fetched:https://raw.githubusercontent.com/headroomlabs-ai/headroom/main/README.md]
- **Content-aware compressor routing**: CacheAligner → ContentRouter → SmartCrusher (JSON), CodeCompressor (AST for Python/JS/TS/Go/Rust/Java/C/C++/Perl), Kompress-v2-base (HuggingFace text model trained on agentic traces) [VERIFIED-fetched:https://raw.githubusercontent.com/headroomlabs-ai/headroom/main/README.md]
- **Live-zone compression / KV-cache hygiene**: only new bytes are compressed; the frozen prefix stays byte-identical so provider prompt cache is not busted; history is never dropped; CacheAligner warns about volatile content that would bust KV-cache prefixes and "never rewrites prompts" [VERIFIED-fetched:https://raw.githubusercontent.com/headroomlabs-ai/headroom/main/README.md]
- **CCR restore mechanics (the note-tier core), four phases** [VERIFIED-fetched:https://headroom-docs.vercel.app/docs/ccr]:
  1. *Compression Store* — original content goes to a local LRU cache under a hash key; compressed output carries a marker: `[1000 items compressed to 20. Retrieve more: hash=abc123]`
  2. *Tool Injection* — a `headroom_retrieve(hash)` tool is injected into the LLM's toolset so the model can pull originals itself
  3. *Response Handler* — intercepts the call, serves from local cache (~1ms), continues the API turn; on Anthropic/OpenAI proxy paths resolution is transparent to the client
  4. *Context Tracker* — across turns it remembers what was compressed and proactively expands cached content when a new query matches it, before the model asks
- **CCR retention knobs**: proxy originals kept 1800 s (30 min) default; `HEADROOM_CCR_TTL_SECONDS` raises it; effective TTL visible at `/v1/retrieve/stats`; SDK config exposes `storeMaxEntries` (1000), `storeTtlSeconds`, `injectTool`, `injectRetrievalMarker`; message-level CCR via IntelligentContext was RETIRED — tool-output CCR (SmartCrusher/ContentRouter) remains supported [VERIFIED-fetched:https://headroom-docs.vercel.app/docs/ccr]
- **Output token reduction (off by default)**: `HEADROOM_OUTPUT_SHAPER=1` enables verbosity steering ("be terse…" appended after system prompt so cache still hits) and effort routing (dials reasoning effort down on routine resume-after-tool turns, clamps only — never raises); savings reported as counterfactual estimate with 95% CI, or measured via a 10% unshaped holdout (`HEADROOM_OUTPUT_HOLDOUT=0.1`); settings hot-synced to a running proxy via loopback `POST /admin/runtime-env` [VERIFIED-fetched:https://raw.githubusercontent.com/headroomlabs-ai/headroom/main/README.md]
- **`headroom learn`**: mines failed sessions, writes corrections to `CLAUDE.local.md` (default, gitignored) or `CLAUDE.md`/`AGENTS.md`/`GEMINI.md` [VERIFIED-fetched:https://raw.githubusercontent.com/headroomlabs-ai/headroom/main/README.md]
- **Cross-agent shared memory**: shared store across Claude/Codex/Gemini/Grok with agent provenance and auto-dedup; `SharedContext().put/.get` for multi-agent passing; wrapping Claude installs Serena at user scope unless `--code-memory none` [VERIFIED-fetched:https://raw.githubusercontent.com/headroomlabs-ai/headroom/main/README.md]
- **Accuracy + savings evidence**: workload table (code search 92%, SRE debugging 92%, issue triage 73%, codebase exploration 47%); GSM8K ±0.000, TruthfulQA +0.030, SQuAD v2 97% @19% compression, BFCL 97% @32% compression; reproducible via `python -m headroom.evals suite --tier 1` [VERIFIED-fetched:https://raw.githubusercontent.com/headroomlabs-ai/headroom/main/README.md]

## Per-feature verdict
| Feature | Type | LastHarness landing | Rationale |
|---|---|---|---|
| Reversible CCR — compress aggressively, cache original locally, retrieve on demand within TTL | 🧩 Mechanism only | §7.1 design-note | The recorded disposition, confirmed: lossless compression removes the aggressive-vs-safe tradeoff. LastHarness keeps it as a design note because the delivery vehicle (a standing proxy process between agent and provider) violates the ephemeral-worker invariant even though the mechanism is sound. |
| Restore mechanics: hash marker in compressed output + injected `headroom_retrieve` tool + ~1ms local LRU serve + proactive Context Tracker expansion | 🧩 Mechanism only | §7.1 design-note detail | The marker+handle pattern is exactly how LastHarness would expose bounded re-expansion of harvested/compressed context without shipping full originals; TTL'd retention maps onto department-scoped gated memory expiry. |
| Live-zone compression preserving byte-identical frozen prefix (KV-cache hygiene) | 🧩 Mechanism only | §7.1 design-note | Compress-only-the-new-bytes is the correct refinement order for any LastHarness-side context trimming: never mutate history that upstream caches depend on. |
| Output shaper: verbosity steering + clamp-only effort routing + CI-banded honest estimates + holdout control group | 🧩 Mechanism only | Validates existing §7.1 output budget | External evidence that output-budget steering works without accuracy loss, and its measurement honesty (counterfactual estimate + holdout ground truth) is the audit shape LastHarness's own budget enforcement should report against. |
| CacheAligner volatile-content warnings | 🧩 Mechanism only | Kernel request-shaping note | Cheap detection of cache-busting content; transfers as a warning pass, not a rewriter. |
| Cross-agent auto-dedup memory store | ❌ Conflict-skip | — | Memory shared freely across agents contradicts department-scoped gated memory; LastHarness memory is partitioned by dept with allow-listed access, not pooled. |
| Standing local proxy / wrapped long-running session | ❌ Conflict-skip | — | A permanent middleware process is exactly the standing-process shape LastHarness forbids for workers; any adoption would have to live inside kernel-mediated request paths instead. |
| `headroom learn` failure mining into rules files | 🧩 Mechanism only | Adjacent to compaction harvests | Same harvest-failures-into-guidance loop LastHarness already runs at compaction; no new mechanism needed. |
| Serena auto-install at user scope during wrap | ❌ Conflict-skip | — | Silent third-party dependency injected into user config; violates explicit-consent install discipline. |

## Notable absences
No decision-log or audit-journal integration — compression events are observable via stats endpoints but not persisted as reviewable decisions. TTL expiry silently discards originals after 30 min default, which for long autonomous runs is a data-loss window unless retuned (documented but easy to miss). Message-level CCR was retired, narrowing reversibility to tool outputs. The org-scale offering (SSO, centralized rollout) is a separate commercial engagement outside the Apache-2.0 repo. x86 builds need AVX2 for ONNX-backed features (falls back to BM25/heuristics otherwise); two runtime assets (ONNX runtime, HF model) are fetched over TLS unless pre-provisioned — relevant to air-gapped installs.
