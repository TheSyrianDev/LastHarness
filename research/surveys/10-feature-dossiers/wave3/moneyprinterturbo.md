# MoneyPrinterTurbo — Feature Dossier
Registry: #17 | Category: 07 | Verified: 115,755 stars, MIT, pushed 2026-08-24 (GitHub API 2026-08-24)

Note-tier dossier. Recorded disposition: staged media-pipeline decomposition → §16.4 video-gen fast-follow design-note. The value here is not the product (an automated short-video generator) but the proof that short-video synthesis decomposes cleanly into independently swappable stages. Stage pipeline as documented: **① script** (LLM-generated or user-supplied, multilingual) → **② footage acquisition** (keyword-matched stock from Pexels/Pixabay/Coverr, user-local materials, or AI-generated clips) → **③ voiceover** (multi-provider TTS with live preview) → **④ subtitles** (TTS-timestamp or local Whisper transcription, styled) → **⑤ background music** (random/specified, volume-mixed) → **⑥ composition/render** (ffmpeg, 1080x1920 or 1920x1080) → **⑦ optional auto-publish** (cloud). Each stage is provider-configurable, which is exactly the seam LastHarness's §16.4 fast-follow design-note should formalize.

## Notable absences
No provenance or audit trail on generated assets (which prompt/provider produced which clip is not persisted in the documented flow) — LastHarness's immutable SQLite decision log would need to wrap every stage dispatch. No quality gate anywhere: nothing scores the rendered candidate before delivery; pick-best is manual. Subtitles assume the TTS audio exists first (edge mode derives timings from TTS), so the pipeline is strictly sequential with no documented resume/checkpoint semantics mid-chain. No local image/video generation — the "AI footage" path is exclusively the cloud WaveSpeed service. Publishing credentials live in `config.toml` alongside everything else, with no secret isolation.
