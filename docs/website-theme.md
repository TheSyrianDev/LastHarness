# The website wearing your theme

The Last AI website (`thesyriandev.github.io/lastsoft`, and wherever it is served) has a theme picker with
Omarchy's own palettes in it. On Omarchy with this edition installed, it does better than that: it reads the
theme your desktop is using and changes the moment you switch, so the page and the rest of the screen agree.

It is done with two small things, no account and no cloud:

- **`lastai-theme`**, a service that reads `~/.local/state/omarchy/current/theme` and answers on loopback.
- **`theme.js`** on the site, which asks it once and then listens for changes.

## What the service answers

It binds `127.0.0.1` only, on port `8787` (change it with `LASTAI_THEME_PORT`, on both sides if you do).

    GET /theme.json

```json
{
  "name": "catppuccin",
  "mode": "dark",
  "palette": {
    "mode": "dark",
    "background": "#1e1e2e",
    "foreground": "#cdd6f4",
    "accent": "#89b4fa",
    "orange": "#f6b6ab",
    "green": "#a6e3a1",
    "...": "every key in colors.toml, as written"
  }
}
```

    GET /events

Server-sent events, one `data:` line per theme change (and one immediately on connect), so an open page
recolours without a reload. A `: keep-alive` comment every fifteen seconds keeps the connection honest.

`404` on `/theme.json` means there is no Omarchy theme to read; the site falls back to its own picker. That is
also all a non-Omarchy visitor ever sees.

The service never writes anything, holds no state beyond the theme it last read, and needs no privileges. It
parses `colors.toml` as flat `key = "value"` lines. `theme.name` beside the theme folder is the name; the folder
name is the fallback.

## Turning it on

The package does it for you:

    sudo pacman -U LastAI-omarchy-*.pkg.tar.zst   # then
    lastai-omarchy-setup                          # enables the user unit

From a source checkout, `scripts/install-omarchy.sh` installs the binary into `~/.local/bin`, writes the unit
into `~/.config/systemd/user` and enables it. Both commands are safe to run again, and both `--uninstall`
stop and remove the service.

By hand:

    cargo build --release -p lh-theme
    ./target/release/lastai-theme                 # foreground, banner on stderr
    ./target/release/lastai-theme --print         # the JSON, then exit
    ./target/release/lastai-theme --port 9000     # another port

Check it:

    curl -s http://127.0.0.1:8787/theme.json
    curl -N http://127.0.0.1:8787/events          # leave open, switch theme in another window

Switch the theme, and the second command prints a new line within a second.

## Why loopback and CORS

A public page cannot read your files. It can ask a local program, if that program says it is willing: the
service echoes the `Origin` that asked and answers Chrome's private-network preflight with
`Access-Control-Allow-Private-Network: true`, so the site's `fetch` is allowed and any other page gets nothing
it could not already guess. The answer travels from your machine to your machine.

If a browser refuses the loopback request (some builds are stricter about `http://127.0.0.1` from an HTTPS
page), the picker still works and the last theme the service reported is kept for the next visit.

## On the site

- `themes.css` and `themes.js` are generated by `tools/build-themes.py` from the `colors.toml` files Omarchy
  ships, so the palettes in the picker are the real ones.
- `theme.js` paints a palette into CSS custom properties, offers the picker on <kbd>T</kbd>, and remembers the
  choice (`lastai-site-theme`: absent or `auto` follows the desktop, anything else pins that theme).
- The wordmark, Figure 1 and every surface read those properties, so a theme changes the whole page at once.
