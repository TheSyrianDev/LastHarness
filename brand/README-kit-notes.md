# LastHarness motion kit (2026-10-30)

User asked for "real" animation instead of HTML/JS simulation, packaged as a zip + prompt for **Claude Code** (not claude.ai chat).

Delivered `lastharness-motion-kit.zip`:
- `PROMPT.md`: brief for Claude Code in five phases: (1) polish the mark animation (arcs, overlapping action, blinks, loop seam); (2) moods as Lottie markers (idle, working, thinking, done, asleep, needs you, failed); (3) six ball bots as Lottie (tool moves first, then a 56°/38° turn and look-up, faked 3D); (4) exports (Lottie per palette, dotLottie if supported, MP4/WebM-alpha/GIF/APNG, tray sprites, optional social video); (5) a QA script (loop seam, safe-circle bounds, eye and slot limits, a second player). Ground rules: don't redesign, keep a re-runnable generator, look at renders, keep the timing sheet in sync.
- `timing-sheet.md`: 60 fps, 512 px comp (64 grid × 8). Spawn 0–84; loop 84–492. Markers: spawn, loop, slot-in 126, glance 151, hold 181, slot-out 282, look-back 294, idle 360.
- `lottie/` v0 (generated by `tools/build_mark.py`): palettes grove-dark, grove-light, tokyo-night, mono-black, each with and without background. Layers: slot-ring, slot, eyes (child of face; pivot 27,37), face (pivot 27,56).
- `renders/`: MP4 (dark, light), WebM with alpha, GIFs (loop and intro).
- `source/`: mark-rig.svg (named parts and pivots), tokens.json, brand-geometry.js, bot-tools.js.
- `viewer/`: lottie-web player with marker buttons, scrubber and 0.25× speed (serve with `python3 -m http.server`).
- `reference/`: v0 key frames, frames of the web prototype, identity page v1.

How to use: unzip, run `claude` in the folder, say "Read PROMPT.md and do it."
Rive was ruled out as the main format (the editor is needed); Lottie was chosen for its players on web, Android and iOS, and in Rust (to verify).
